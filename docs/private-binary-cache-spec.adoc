= Private Binary Cache — build once, substitute everywhere
:toc: left
:toclevels: 3
:icons: font

**Status:** 📐 target architecture — decided 2026-10-10, not built +
**Scope:** how the seedmatic hosts stop rebuilding the same paths, and where those paths are kept

[NOTE]
====
This spec states the *target* only. The way there from today's state (each host builds, and a
`cachix watch-store` daemon published every new store path to the public `nxmatic` cache) is
described in the rke2lab migration atlas, `docs/architecture/atlas/fabric-control-plane.adoc`,
section _The private binary cache_.

Every figure marked *measured* was read on 2026-10-10 from store paths that already existed. No
flake was evaluated to get it.
====

== Overview

The seedmatic hosts share most of one configuration, so they run mostly the same packages. Today
each host builds them again. The cache makes a path **built once and substituted everywhere**:

* **one builder** builds every host's configuration from a pushed commit;
* what it builds reaches an **attic** server, which runs in an Incus container on bioskop. On Linux
  an `attic watch-store` daemon uploads it; on darwin a fill job pushes it explicitly;
* the hosts only **substitute** from it, and **every read needs a token**.

[cols="1,3",options="header"]
|===
| Property | What it gives

| One build per path
| The four host closures add up to 32 GiB, but their union is 15.7 GiB, and only 1.6 GiB of that union
is not already on cache.nixos.org (measured, see <<sizing>>). That 1.6 GiB is the part the hosts
rebuild today.

| Latest versions only
| The cache keeps what the hosts run now, not a history, and it skips the paths whose signature says
an upstream cache serves them.

| Write tokens on the builders only
| Only the builders upload: the watch-store daemon on bioskop-nixos and the darwin fill job. Every
other consumer holds a read token, nothing more.

| Private by authentication
| The cache is created **without** `--public`, so an anonymous request is refused (see
<<read-test>>). Listening on the fabric segment only, never on a public port, adds to that. It does
not replace it.
|===

The motive is the incident of 2026-10-10. A daemon pushed every new store path to the public cache.
On a machine whose git config smudge-decrypts sops files, evaluating a dirty rke2lab tree copies
`.secrets` and `.ndh-ssh.d/keys.yaml` in clear into the store, so 52 such copies became public. The
daemon was disabled on every host in `395b34a1`.

This spec brings the cache back, and it does **not** remove that shape: through the watch-store,
plaintext can still reach the cache. It confines it instead. The operator allowed the watch-store on
2026-10-10 on one condition, that reads are authenticated. The real fix is an attic fork that refuses
such paths at upload (see <<attic-fork>>), and, upstream of attic, no plaintext on disk in a flake
tree.

== Vocabulary

[cols="1,3",options="header"]
|===
| Term | Meaning

| *nerd-nixos*
| The Tart NixOS guest on a bare-metal (`bioskop-nixos`, `nikopol-nixos`). It hosts Incus. Its
`/nix/store` is an overlay of read-only EROFS layers over a ZFS upper.

| *Incus cluster*
| The one Incus service, which ndh configures as part of nerd-nixos. Its members are the two
nerd-nixos: `bioskop` (database leader) and `nikopol` (`database-client`), both online on
2026-10-10. It hosts the rke2lab cluster nodes (project `rke2lab`) and the infrastructure containers
below.

| *attic-nixos*
| The Incus container that runs attic. It exists **on bioskop only**.

| *headscale-nixos*
| The Incus container that runs headscale. There is one **on each bare-metal**; see
link:fabric-control-plane-spec.adoc[the fabric control plane].

| *Builder*
| The machine that evaluates and builds the hosts' configurations and fills the cache. For Linux
this is bioskop's nerd-nixos. For darwin it is a dedicated job on bioskop (see <<who-fills>>).

| *Fill*
| One builder run: build, then upload (by the watch-store on Linux, by an explicit push on darwin),
then keep alive.

| *Read token*
| An attic token that can pull from the cache and nothing else. Every substituter of attic holds one
(see <<secrets>>).

| *Ours*
| A path that has no `cache.nixos.org-1` or flox signature in the local Nix DB.

| *Truly ours*
| A path that is ours **and** whose narinfo returns 404 on cache.nixos.org. Only these belong in the
cache.

| *Live set*
| The paths the cache must keep: for each host, the closure of its latest built generation, plus the
generation it currently runs.
|===

== Who fills the cache — the central decision

[cols="1,2,2",options="header"]
|===
| | (a) every host pushes what it builds | (b) one builder, from a pushed commit ✅

| Write tokens
| one on every machine
| one per builder platform

| Evaluated tree
| whatever is checked out, dirty included
| a pushed revision (`github:` or `git+file` at a `rev`), so the tree is clean

| Secret exposure
| every dirty evaluation is again a leak path, into a private cache instead of a public one. That is
the incident's shape.
| the fill's own evaluation keeps sops files encrypted, as git holds them. The Linux watch-store
also sees the remote builds bioskop-nixos serves (see <<watch-store-sees>>).

| `allow-dirty = false`
| unusable: the hosts are dev seats, and the dev loop evaluates dirty trees all day
| fits: nobody develops on the builder

| Builds per path
| one per host that needs it, minus the substitution races
| one
|===

**Recommendation: (b).** For Linux, the builder is bioskop's nerd-nixos. It already serves remote
builds (`/etc/nix/machines` → `ssh-ng://root@bioskop-nixos`), and it sits next to attic.

On Linux the upload is an **`attic watch-store` daemon** on bioskop-nixos. The operator allowed it
on 2026-10-10, on the condition that reads are authenticated. On darwin the upload stays an
**explicit push** from the fill job, for a reason given below.

[[watch-store-sees]]
=== What bioskop-nixos's watch-store also uploads

The daemon watches the whole store, not the fill. Read in attic `client/src/command/watch_store.rs`
at `7a19204d`:

* when a path becomes valid, the daemon skips it if its name ends in `.drv` or `-source`. That is a
  test on the **name**, done once, when the path appears;
* for every path it keeps, it pushes the **closure** by default (`--no-closure` is a hidden flag).
  An output that references a flake source therefore carries that source, whatever its name.

bioskop-nixos realises three kinds of paths besides the fill, so all three now reach the cache:

[cols="1,2",options="header"]
|===
| Origin | What lands in the cache

| the dev seats' remote builds (`ssh-ng`, `/etc/nix/machines` on bioskop and nikopol)
| the outputs of derivations evaluated from **dirty trees**. Their input `-source` copies, plaintext
included, are skipped by name, but an output that references one carries it in its closure.

| the pods' remote builds (rke2lab's flox runtime, Part 2: `max-jobs = 0` → `ssh-ng://nix-store.{host}-nixos`)
| the unknown packages a workload asked for, built from inputs the workload chose

| anything realised on bioskop-nixos itself
| its own generations, and what a session there builds
|===

This is **accepted under authenticated reads**. A plaintext copy that reaches the cache can be read
only by a holder of a read token, all of which are machines of the fabric (see <<secrets>>). It is
not fixed by them. The fix is the fork in <<attic-fork>>.

The darwin side keeps an explicit push because there the watch-store would run **on the dev seat
itself**. bioskop's store receives every dirty evaluation directly, not just its remote builds.
The darwin fill job pushes only the closures it built from a pushed revision.

=== The darwin paths need a darwin builder

nerd-nixos is Linux, and some of the darwin hosts' paths exist only on darwin. Measured on the two
darwin system closures:

[cols="2,1",options="header"]
|===
| Darwin "ours" paths | Size

| shared by bioskop and nikopol | 0.97 GiB
| bioskop only | 0.20 GiB
| nikopol only | < 0.01 GiB
| of which truly ours (not on cache.nixos.org) | 0.78 GiB
|===

The two darwin hosts overlap almost completely, so **one Mac builds both**, and that Mac is bioskop.
nix-darwin builds `darwinConfigurations.nikopol.system` on any `aarch64-darwin` machine, and nikopol
is a guest on a foreign, MDM-managed bare-metal.

bioskop is also the dev seat, so the darwin fill does not run in the operator's session. It is a
dedicated launchd job:

* it runs under its own user;
* it evaluates a pushed revision, with `--option allow-dirty false` on its own command line;
* it reads a darwin write token that only that user can read.

The operator's `nix.conf` keeps `allow-dirty` at its default, because a global `false` would break
the Maven build of manifests-core (`nix run .#stage-*-crd`) and the whole dev loop.

=== The upstream filter — signatures, for the watch-store and the push alike

attic's filter is a setting **of the cache**, on the server: `upstream-cache-key-names`. Both
`watch-store` and `push` read it. For each path of the closure, the client reads the path's
signatures **from the local Nix DB**, splits each at the `:`, and drops the path if the key name is
in the list. It asks no upstream server (attic `client/src/push.rs:449-466`).

The list is `cache.nixos.org-1`, `flox-cache-public-1`, `floxhub-1`, plus the layer key below. It
is **not** ndh's `trusted-public-keys` as they stand:

[cols="1,3",options="header"]
|===
| Key name | Why it stays out of the list

| `io-nxmatic-nix-darwin-home`
| the fleet's own key, in `secret-key-files`, so nix signs **every local build** with it (about 1170
of our paths carry it, measured). In the list, it would leave the cache empty.

| `nxmatic.cachix.org-1`
| about a hundred of our paths carry it, but the public cache no longer serves any of them (690 of
690 truly-ours paths answer 404, measured after the purge). In the list, those paths would be served
by nobody.
|===

The filter misses what upstream serves but no local signature says: **297 paths (0.66 GiB)** across
the four host closures. On bioskop-nixos, 96 of its 289 such paths are in the EROFS layers,
registered from `closureInfo` without signatures (`nix-store --load-db`,
`modules/nixos/bringup-disk-image-common.sh:131`). The others were built locally. They cost disk,
not a leak. The darwin push may add a narinfo query to upstream before pushing; the watch-store
cannot until the fork.

=== Excluding the EROFS layers' own paths — a layer key

A path that is in the layers is already on every consumer that mounts them, so it should not be
uploaded. Paths substituted from upstream into the layers would be excluded by their signature, if
the registration kept it. The paths **we** built into the layers carry only
`io-nxmatic-nix-darwin-home`, like every other build of ours. A key of their own separates them:

. **a dedicated key**, `nerd-erofs-layers-1`. It is generated with
  `nix key generate-secret --key-name nerd-erofs-layers-1`, and its secret half is sops-encrypted
  in ndh. It must **never** be in `secret-key-files`, or every build would be signed with it and
  excluded;
. **sign the layers only**, when their lower DB is generated, once per layer set: load the
  registration into a scratch store, then run
  `nix store sign --store 'local?root={scratch}' --key-file {key} --recursive {layer roots}`. That
  signed DB ships with the layers. ⚠️ This is a step on the builder, **not** a derivation: in a
  derivation, the secret key would enter the store, and from there the cache;
. **carry the signatures to nerd-nixos's own DB**, which is loaded from the unsigned registration
  today. Right after the load, `nix store copy-sigs -s 'local?root={signed lower}' -r {roots}`
  imports them without the secret. That `copy-sigs` accepts a local store as its source is to verify;
. **add `nerd-erofs-layers-1` to `upstream-cache-key-names`.** No fork is needed: attic compares
  key names only (`push.rs:449-466`). A real signature still proves where the path came from.

The upstream paths inside the layers can be signed with the layer key too, so that everything in a
layer is excluded, or given back their own signature with
`nix store copy-sigs -s https://cache.nixos.org -r {roots}`.

Measured on bioskop-nixos, the gain is small today: 115 of its 611 ours paths are in the layers,
and the running generation is not, because the layers predate it. The key prevents duplicates; the
delta since the layers is what the cache is for.

=== The secret guard — on the darwin push only

Every host's system closure already carries sops files **by design**: sops-nix puts the encrypted
file in the store. Measured, by counts only: `ndh-.secrets` (16 `ENC[` values), `keys.yaml` (10
`ENC[`, no `PRIVATE KEY` marker, its 77 plain values are public by design) and `cache-trust.yaml`
(2 `ENC[`). So the guard judges **content, not names**. It refuses the whole push if any candidate
path holds:

* a `# sops:encrypted` annotation followed by anything but an `ENC[` value (the rule of
  <<attic-fork>>);
* a private-key armour header followed by a body;
* a GitHub token shape (`gh[opsu]_…`, `github_pat_…`).

It runs where there is a push step to run it in: the darwin fill. The Linux watch-store has no such
step, and attic offers no hook, so the same guard on Linux **is** the fork.

[[retention]]
== Retention — latest only

=== What attic actually does

Read in attic's source at `7a19204d` (2026-07-06), not taken from the usual summary:

[cols="1,3",options="header"]
|===
| Fact | Source

| An object is collected when **both** `created_at` and `last_accessed_at` are older than the
retention period.
| `server/src/gc.rs:108-123`

| Only a **NAR download** bumps `last_accessed_at`. A narinfo lookup does not.
| `server/src/api/binary_cache.rs:212` (bump) and `:115-160` (narinfo, no bump)

| A retention of **0 disables GC**, and 0 is the default.
| `gc.rs:95`, `config.rs:561-563`

| Re-pushing a path the cache already holds never reaches the server, so it refreshes nothing.
| `client/src/push.rs:478-484`

| There is **no pinning and no single-path delete**. The only DELETE destroys a whole cache.
| `server/src/api/v1/mod.rs:10-37`

| `attic cache configure` **without** `--retention-period` resets the cache's retention to the
global default.
| `client/src/command/cache.rs:225-229`

| On SQLite, a GC run reaps at most **500 chunks**; on PostgreSQL, 65535.
| `gc.rs:178-190`
|===

=== How "latest only" is obtained

Since nothing can be pinned or deleted path by path, "latest only" is **a retention period plus a
keep-alive**:

. per cache, `retention-period = 14 days`, set in the same declarative step as every other cache
  setting, so a later `configure` cannot reset it silently;
. at the end of every fill, the builder **downloads the NAR** of every path in the live set. It uses
  a plain HTTP GET of the narinfo's `URL`, because the builder already holds those paths locally and
  nix would never substitute them;
. a superseded path stops being downloaded, so it is collected about 14 days after the last fill
  that still needed it.

[cols="1,3",options="header"]
|===
| Guarantee | Holds when

| a host never loses the substitute of the closure it runs
| that closure is in the live set. The latest built generation always is. The running one is
included once the builder knows it, which is open below. Until then the guarantee is **bounded**: a
host that has not switched for more than the retention period loses re-substitution of its running
closure. It still runs, and still holds every path locally.
|===

=== GC cadence and database — PostgreSQL

One full set of truly-ours paths is about 6.8 GiB of NAR, roughly 111 000 chunks at FastCDC's
64 KiB average, and a nixpkgs bump orphans nearly the whole set (measured below), about once a week.

* **SQLite**, 500 chunks per run: at the default 12-hour interval, reaping one set takes 223 runs,
  that is 111 days. At a 1-hour interval it takes 9.3 days, and the capacity is 84 000 chunks a week
  against 111 000 orphaned. **GC never catches up, and the disk grows without bound.**
* **PostgreSQL**, 65535 chunks per run: two runs reap a set.

So attic-nixos runs PostgreSQL next to atticd (nixpkgs `services.postgresql`), with a GC interval
of 1 hour. This is also what attic's own template recommends for production
(`server/src/config-template.toml:44`).

=== The arithmetic

[cols="2,2,1",options="header"]
|===
| Term | Computation | GiB

| L — the latest set, NAR | 1.56 (systems) + 5.25 (flox) + U (unmeasured: package outputs and
cluster node closures) | 6.81 + U
| L~c~ — compressed | 6.81 × 0.26 | 1.77 + 0.26 U
| in-flight generation | a bump replaces nearly the whole set: one more L~c~ | 1.77
| superseded tail | bumps within the retention period: 14 days ÷ 7 = 2 sets | 3.54
| *steady-state worst case* | 4 × L~c~ | *7.1 + 1.04 U*
|===

Two things are deliberately left out:

* chunk dedup between successive versions of the same package, which only makes the real figure
  smaller;
* PostgreSQL's footprint, for which attic publishes no guidance (unverified). It is small next to
  the chunks: one row per chunk and per object.

=== Quota proposal

A dataset `tank/nerd/attic` with **`quota=32G`**, holding the chunk storage and the PostgreSQL data
directory as children. That is 19 % of the 168 GiB available. The quota covers three things:

* the measured 7.1 GiB, × 3 for headroom;
* U, the unmeasured package outputs, and the flox environments of the Linux side;
* a 30-day retention, should the lag bound need to grow: 7 × L~c~ = 12.4 GiB.

It sits next to the other `nerd/*` datasets declared in `modules/nixos/zfs-disko-config.nix`, and is
passed to attic-nixos as an Incus disk device. It is **not** replicated to the `recover` pool,
because the builder can refill the cache from scratch. The signing key does not live on it (see
<<secrets>>).

[cols="1,1",options="header"]
|===
| ✅ Do | ❌ Don't

| watch `used` against the quota: above 75 %, GC is not keeping up
| put the chunks under `/nix/store` or in the container's root volume, which the overlay and the
container's lifecycle would govern
|===

[[container-store]]
== The containers' `/nix/store` — an overlay on nerd-nixos's EROFS lowers

Both attic-nixos and headscale-nixos mount their `/nix/store` as an overlay **from the start** (the
operator's choice: there is no plain-store first increment). The lowers are the EROFS layers that
nerd-nixos already mounts. The upper is a per-container ZFS volume. The containers' system closures
therefore overlap nerd-nixos's, and the upper receives only the **delta**.

....

[cols="1,3",options="header"]
|===
| Rule | Why

| the lowers are the **EROFS layers**, never nerd-nixos's merged `/nix/store`
| the merged store changes as nerd-nixos activates generations, and in OverlayFS a lower that changes
while mounted is undefined behaviour

| pass the **mount points** (`/nix/.ro-store`, `.002`, `.003`) read-only, never `/dev/vdX`
| measured: the device names do not follow the layer index (vdh, vdf, vdg), while ndh already mounts
the layers by label. Use the post-`switch_root` paths, not the initrd's `/sysroot/…`.

| lowerdir order = nerd-nixos's, newest first (`.003:.002:.ro-store`), **projected** from
`modules/nixos/erofs-store-layers.nix`
| overlayfs reads left to right. A second, hand-written list would drift.

| nix side: `local-overlay-store` with a lower that is a **complete** read-only store
| nix then knows which paths come from the lower, so it never rebuilds or collects them. The layers
carry no nix DB today (measured), so the lower DB is generated **once per layer set** from the same
`closureInfo` registration (`baseClosureInfo`, `fleetRuntimeClosureInfo` in
`modules/nixos/bringup-zfs-disk-image.nix`) and shipped with the layers.

| same invariants as `modules/nixos/erofs-store-mount.nix`
| immutable labels and UUIDs, and `index=on`, which refuses a changed lower (ESTALE)
|===

[source,ini]
----
# the shape of the container's store setting — {ro-root} and {upper} are the mount points
store = local-overlay://?lower-store=local://?root={ro-root}%26read-only=true&upper-layer={upper}&check-mount=true
----

=== Three tiers of store, one immutable base

attic-nixos and headscale-nixos are the first users of this mechanism, not the only ones. The rke2lab
cluster nodes are Incus containers on the same members, and their workloads mount a store of their
own through the flox NRI plugin. Each tier inherits the base of the tier below and substitutes only
its delta, from attic:

[cols="1,2,2",options="header"]
|===
| Tier | Its store | What it substitutes from attic

| 1 — nerd-nixos
| EROFS layers plus a ZFS upper
| its generations beyond the layers

| 2 — containers (infrastructure and cluster nodes)
| overlay on the EROFS layers (this section)
| its configuration's delta, then for a node the `FloxEnv` closures that the flox controller realises
and GC-roots. A node collects on disk pressure (rke2lab node-base: `min-free = 128MB`,
`max-free = 1GB`), so it re-substitutes what it collected.

| 3 — pods
| overlay whose lower is the node's `/nix`, bind-mounted read-only by
`flox-nri-overlay-hook.sh`, and whose upper is a 2 GiB tmpfs or a PVC
| nothing directly: they read the node's store. Unknown packages are built remotely on
`{bioskop,nikopol}-nixos` (`max-jobs = 0`) and land in the pod's upper. Built on bioskop-nixos,
they **are** uploaded by its watch-store (see <<watch-store-sees>>).
|===

This is the intent of building the mechanism in ndh as a module rather than inside one service.
Tiers 2 (nodes) and 3 are adopted in rke2lab; see its atlas, section _The private binary cache_.

=== Boot, then switch — the container never evaluates a flake

[mermaid]
....
sequenceDiagram
  autonumber
  participant Op as Operator (bioskop)
  participant NN as nerd-nixos
  participant C as Incus container
  Note over C: boots a small boot.isContainer generation<br/>whose paths are already in the shared lowers
  Op->>NN: build the target configuration (same lock as the layers)
  NN->>NN: evaluate and build, never in the container
  NN->>C: nix copy --to the closure (the delta lands in the upper)
  C->>C: switch-to-configuration on the copied closure
  Note over C: no flake source ever enters the container<br/>and attic's bootstrap needs no cache
....

Four conditions:

. **share the paths, not the boot.** nerd-nixos's generation is a VM's (kernel, initrd, EROFS mounts
  in the initrd) and cannot boot as an Incus container;
. **build the containers and the layers from the same lock**, or the upper fills with copies;
. **the delta does not come from the cache that does not exist yet.** attic's own container is filled
  by `nix copy`, not by substitution;
. **the container never evaluates a flake.** Evaluation, the incident's vector, stays on nerd-nixos.

== Hosting — one Incus service, two owners of instances

The Incus service already belongs to ndh: it is part of nerd-nixos's configuration
(`modules/nixos/incus.nix`, `incus-cluster.nix`). What ndh does not do yet is declare an **instance**.
On that one service, instances will have two owners:

[cols="1,1,2",options="header"]
|===
| Owner | Project | Instances

| rke2lab, through CAPN
| `rke2lab`
| the cluster nodes, which come and go with each grow

| ndh
| its own project, not `rke2lab`
| attic-nixos and headscale-nixos, which outlive any cluster
|===

The infrastructure containers stay out of `rke2lab`, so nothing that tears down or re-grows a
cluster can reach them. This is the single-owner rule applied to a shared service.

=== Placement is stated, never left to Incus

In a cluster, an instance created without a `target` lands on a member that Incus chooses. These
containers depend on things that exist on **one** member only: their lowers (that member's
`/nix/.ro-store*`), and for attic the `nerd/attic` dataset. So:

* attic-nixos has `target = bioskop`;
* each headscale-nixos has the member of its own bare-metal as its target;
* none of them migrates when its member is evacuated. Incus's instance option `cluster.evacuate`
  should be `stop`; that option name and value are to verify against the pinned Incus.

=== One module for both containers

attic-nixos and headscale-nixos are the first two instances ndh declares, and they share one module:

* the container declaration, with its project and its target;
* the overlay store described above;
* the boot-then-switch delivery.

Each service then adds only its own NixOS configuration: `services.atticd` plus PostgreSQL, or the
existing `modules/nixos/headscale-daemon.nix`. There is no second way to host a service in Incus.

[[secrets]]
== Secrets, tokens and substituters

* attic's server secret (`ATTIC_SERVER_TOKEN_RS256_SECRET_BASE64`, through `services.atticd`'s
  `environmentFile`), the cache's signing key, the layer key and every token are **sops-encrypted at
  rest**. They are decrypted only into `/run/secrets` (tmpfs, root-only, mode 0400), and never sit in a
  flake tree that anyone evaluates dirty.
* The cache is created **without** `--public`. Tokens come from `atticadm make-token`: a write token
  (`--push`, plus `--pull` for the keep-alive) per builder platform, and a **read token** (`--pull`
  only) per consumer class.
* nix reads a token from its `netrc-file`, as the `password` of the attic host's `machine` entry. That
  is the same entry `attic use` writes (`client/src/command/use.rs:54-68`, `nix_netrc.rs:96`).
* Each consumer's `nix.conf` gains attic's fabric URL and public key, **after** cache.nixos.org in
  substituter order, and a `netrc-file` pointing at its decrypted token.

[cols="1,2,1",options="header"]
|===
| Consumer | Where its read token lives | Encrypted at rest

| darwin hosts (bioskop, nikopol)
| sops-nix secret under `/run/secrets/nix-darwin-home/`, named by `nix.settings.netrc-file`, read by
the nix daemon
| ndh `.secrets`

| nerd-nixos (both)
| sops-nix secret under `/run/secrets/`, named by `nix.settings.netrc-file`
| ndh `.secrets`

| attic-nixos, headscale-nixos
| **none**: they never substitute. Their closure arrives by `nix copy` from nerd-nixos (boot, then
switch)
| —

| cluster nodes
| the node's sops-nix secret (rke2lab `nixos/sops.nix`), named by the node-base `netrc-file`. The flox
controller realises `FloxEnv` closures through the node's nix daemon, so it uses the same token.
| rke2lab sops

| pods (flox NRI)
| **none, recommended**: Part 2 sets `builders-use-substitutes = true`, so the remote builder
substitutes with its own token and copies the result back. If a pod ever has to substitute directly,
its token is an NRI read-only mount next to `builder.conf`, materialised at synth time, and never
baked into an image.
| rke2lab sops
|===

[[read-test]]
=== The test the implementation must pass — an anonymous read is refused

[source,bash]
----
# a path known to be in the cache: {hash} of the fill's last system closure
curl -s -o /dev/null -w '%{http_code}\n' "https://{attic}/{cache}/{hash}.narinfo"
# → 401  (anonymous: refused)
curl -s -o /dev/null -w '%{http_code}\n' --netrc-file {netrc} "https://{attic}/{cache}/{hash}.narinfo"
# → 200  (read token)
----

attic answers **401** to a client without the permission. It deliberately masks a missing cache, a
missing object and a missing permission behind the same `Unauthorized` (`server/src/error.rs:194-205`,
`:218`), so the anonymous answer reveals nothing about what the cache holds. A **200 without a token**
means the cache was created or reconfigured `--public`: the cache is then not private, and this spec's
condition for the watch-store no longer holds.

== Usage patterns

=== ✅ Fill from a pushed revision

[source,bash]
----
# on the builder: a clean tree, by construction
nix build "github:seedmatic/ndh/$REV#nixosConfigurations.bioskop-nixos.config.system.build.toplevel" \
  --option allow-dirty false
----

=== ❌ Push from a dev seat

[source,bash]
----
attic push seedmatic ./result      # from the operator's checkout: one dirty evaluation away from the incident
----

=== ✅ A watch-store on the Linux builder, behind authenticated reads

[source,bash]
----
# on bioskop-nixos, as the daemon's service: the cache was created without --public
attic watch-store seedmatic
----

Allowed under one condition, which <<read-test>> checks: every read needs a token. What it also
uploads is listed in <<watch-store-sees>>.

=== ❌ A watch-store on a dev seat, or towards a cache readable without a token

On bioskop's darwin, the daemon would see every dirty evaluation of the dev loop first-hand. On a
`--public` cache, or a public one like `nxmatic.cachix.org`, it would bring back the incident
itself.

=== ❌ Derive the key-name list from `trusted-public-keys`

That list holds `io-nxmatic-nix-darwin-home`, which signs every local build, so the cache would stay
empty. It also holds `nxmatic.cachix.org-1`, whose paths the public cache no longer serves. Write
the list out: the upstream substituters' key names, plus the layer key.

== Troubleshooting

[cols="2,2,2",options="header"]
|===
| Symptom | Cause | Fix

| the dataset grows week after week
| GC on SQLite, capped at 500 chunks per run
| PostgreSQL, and a 1-hour GC interval

| a superseded path is never collected
| retention 0 (the default), or a `cache configure` that reset it
| set `--retention-period` in the same declarative step as every other cache setting

| a host re-substitutes nothing after a long pause
| its running closure aged out: it was not in the live set
| add the running generations to the live set (open below), or refill

| the cache uploads paths cache.nixos.org serves
| they carry no upstream signature locally: layer registration, or a local rebuild
| the layer key for the layer paths. The rest is disk, until the fork.

| an anonymous narinfo request returns 200
| the cache was created or reconfigured `--public`
| make it private again. Until then the watch-store's condition does not hold, so stop it.

| a host cannot substitute from attic at all
| its `netrc-file` is missing, or its token is expired or has no `--pull`
| check the decrypted token under `/run/secrets` and the `netrc-file` setting

| the cache stays empty
| `io-nxmatic-nix-darwin-home` is in `upstream-cache-key-names`
| remove it: it signs every local build

| the container's store reports a stale file handle (ESTALE)
| a lower changed under `index=on`
| restart the container on the layer set nerd-nixos booted
|===

[[attic-fork]]
== The real fix — an attic fork, later

The read token **confines** a plaintext path that reaches the cache; it does not keep it out. The
fix is upstream of the token: the cache must refuse such a path. attic offers no hook for that, so
it is a fork, meant to be contributed upstream. Decided with the operator on 2026-10-10, for later.

[cols="1,3",options="header"]
|===
| Change | What it does

| a daemon-to-server protocol
| the **server** judges what enters, rather than a filter in each client. The natural place for it
is `get-missing-paths`, the exchange that already opens every push: the server can answer "served
upstream" or "refused" as well as "missing".

| an upstream check by query, not by signature
| ask the upstream caches for the narinfo, instead of reading local signatures. That closes the
297-path gap, and makes the layer key a convenience rather than a necessity.

| a content filter, which refuses
| with the repository's `.sops.yaml` shared to the server: a `# sops:encrypted` annotation followed
by anything but an `ENC[` value marks a decrypted file. Measured on `keys.yaml`: the annotation
survives in clear in both states (9 annotations, each followed by `ENC[` when encrypted, by a `\|`
block when decrypted). A second test, independent of the rules, looks for private-key armour with a
body, an `AGE-SECRET-KEY-1`, and GitHub token shapes, because the `.sops.yaml` itself was once wrong
(2026-08-27).
|===

The filter **refuses**; it never re-encrypts. A `-source` path is addressed by its content, a cache
signature covers the NAR hash, and sops draws a fresh IV at each encryption. A rewritten path would
be a different path, and every closure that references it would have to be rebuilt.

== Open questions

* **Running generations in the live set**: how does the builder learn which generation each host
  runs? Either a read-only report from the host, or a builder-side profile per host that the hosts
  only ever switch to.
* **Flox environments**: in scope or not, and if so, who realises them from a pushed lock. They are
  the largest item measured.
* **Package outputs, cluster node closures and in-cluster env closures**: their size, once a fill has
  built them.
* **Reaching attic from the cluster nodes**: the nodes sit on their bare-metal's `vmnet` segments
  and the clusters on the SaaS tailnet. The route from a node to attic's fabric name, and from
  nikopol's nodes across the bridge, has to be stated.
* **The pod tier's lower changes while mounted**: it is the node's live `/nix`, which the flox
  controller grows and the node's GC shrinks. That is the case this spec forbids for tier 2. The hook
  reconciles the pod's store DB at every container start, which repairs the DB, not the overlayfs
  rule. Whether tier 3 should instead stack on the immutable layers is rke2lab's to decide.
* **uid shifting**: an unprivileged container sees the store's files as `nobody`, and nix expects
  root-owned store paths. Incus `shift` relies on idmapped mounts, and whether EROFS supports them is
  unverified. If it does not: a privileged container or a `raw.idmap`.
* **Dataset creation**: does disko create `tank/nerd/attic` on a pool that is already formatted, or
  does an activation step have to?
* **The TLS leaf behind attic's fabric URL**: from `mammoth-skate-tls`, like the control URL?
* **The public `nxmatic` cachix cache**: kept for non-sensitive outputs, made private, or deleted.
  The `cachix-watch-store` modules, disabled but not yet removed, give way to the attic watch-store
  and go with it.
* **`nix store copy-sigs` from a local store**: whether it accepts `local?root=…` as its source, for
  the layer key.
