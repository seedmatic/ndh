= omo-patch — spec
:toc:

== Purpose

`omo-patch` manages the runtime configuration of oh-my-openagent under `~/.omo/` (the harness).

== Scopes

* Repo-local (inside the project): `.omo/` (hooks, init-deep.json, settings) and `skills/` (or `.agents/skills/`) for project-specific skills.
* Global (the seat): `~/.omo/` and `~/.agents/skills/`.

omo/senpi discover project-local assets first (when trusted), then global.

== Targets

[cols="1,3",options="header"]
|===
| Path | Role
| `~/.omo/omo.jsonc` | main config (agents, categories, task, memory, disabled_skills, provenance)
| `~/.omo/agent/settings.json` | defaultModel, defaultProvider, enabledModels
| `~/.omo/agent/models.json` | providers and models
| `~/.omo/agent/mcp.json` | MCP servers
| `~/.omo/hooks/` | lifecycle hooks (omo-specific; managed by physical presence)
| `~/.omo/plugins/` / extensions | plugins/extensions (managed via omo install/remove)
| `~/.agents/skills/<name>/` | skills (senpi discovers here; managed by omo-patch)
| `~/.agents/.skill-lock.json` | installed-skills lock
|===

== Interface

[source,bash]
----
omo-patch add <skill...>
omo-patch remove <skill...>
omo-patch list
omo-patch profiles
omo-patch --profile <name>
----

== Behavior

- `add <skill>`: copy skill into `~/.agents/skills/` and remove from `disabled_skills` in `omo.jsonc`.
- `remove <skill>`: remove skill from `~/.agents/skills/` and add to `disabled_skills`.
- `list`: show enabled/disabled skills, hooks, agents, plugins.
- `--profile <name>`: apply a full profile fragment (models, categories, agents, concurrency, disabled_skills, hooks, plugins).

NOTE: Memory and MCP server management are left to omo itself; omo-patch only touches `agent/mcp.json` when a profile explicitly lists it.

== Link with skills discovery

`omo-patch` must recompute `disabled_skills` based on the skills present in `~/.agents/skills/` (scan on every run). Hooks are managed by physical presence in `~/.omo/hooks/`.

== Fragments

Directory `modules/home-manager/omo.d/` with one `*.yaml` file per profile.

== Use cases

[cols="1,3",options="header"]
|===
| Command | Effect
| `omo-patch add caveman` | remove `caveman` from `disabled_skills`; verify physical presence.
| `omo-patch remove caveman` | add `caveman` to `disabled_skills`.
| `omo-patch list` | show enabled/disabled skills.
| `omo-patch --profile opencode-go` | switch settings + categories/agents to opencode-go free models.
| `omo-patch --profile omo-default` | restore local Llama state.
| `omo-patch --profile ndh-host-provision` | categories on `agent`/`agent-deep`, litellm concurrency 2, ssh/incus/tailnet skills enabled.
| `omo-patch add <skill>` | copy skill into `~/.agents/skills/` and enable in `disabled_skills`.
| `omo-patch remove <skill>` | remove skill from `~/.agents/skills/` and disable.
| `omo-patch list` | show enabled/disabled skills and hooks.
|===

== Typical chain

NOTE: Single command. `omo-patch` manages both `~/.omo/` and `~/.agents/skills/`. Order: install skills (copy) then enable (disabled_skills).

[source,bash]
----
omo-patch --profile ndh-host-provision
----

sequenceDiagram
  autonumber
  actor Op as Operator

  participant Frag as YAML fragment
  participant Yq as yq-go
  participant Omo as ~/.omo/*
  participant Agents as ~/.agents/skills/

  Op->>Cmd: --profile ndh-host-provision
  Cmd->>Frag: load the profile
  Frag-->>Cmd: targets and patches
  Cmd->>Agents: scan present skills
  Agents-->>Cmd: list
  loop for each target
    alt JSON/JSONC
      Cmd->>Yq: apply set/merge/delete
      Yq->>Omo: write
    else Markdown
      Cmd->>Omo: mdpatch (if applicable)
    end
  end
  Cmd->>Omo: recompute disabled_skills
  Cmd-->>Op: report
