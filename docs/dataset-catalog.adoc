= Dataset Catalog
:toc: left
:toclevels: 3

== Overview

The *dataset catalog* (`catalog.datasets`) is the ZFS dataset *layout* a cluster
needs, merged from contributors and *materialised on the host `tank` pool by
disko* — before any cluster exists. It is the storage twin of
link:network-catalog.adoc[the network catalog] (`catalog.netplan`): a catalog
dimension, populated by the same contributor-merge law, consumed by host modules.

Where the network catalog's cluster underlay is owned by rke2lab and read from its published plan, the dataset
layout under `tank/rke2lab/*` is owned by rke2lab `seed-outcluster` and read from the same plan's `dataplan.json` —
the *dataplan* (the `fabric-plan` input, `flake.nix`). See
rke2lab's link:https://github.com/seedmatic/rke2lab/blob/main/docs/architecture/patterns/dataplan-single-source.adoc[Dataplan SSOT]
for the producer side.

Addresses are never hardcoded (netplan); dataset paths are never hardcoded
(dataplan). Both derive from the catalog.

== Why a catalog dimension, not a literal

The cluster's ZFS tree is a cluster fact: rke2lab's `openebs-zfs` StorageClass and its static persist PV name the
same paths. Held as a literal in the host repo it would drift from rke2lab; as a *catalog dimension fed by the
dataplan* it gets the single-source-of-truth treatment netplan has.

| *ndh* — physical + host concern. The host `nerd/persist` is distinct from the
  cluster `tank/rke2lab/persist`.

| The materialisation *law* — `addDatasetOptions` / `addPostMountHook` /
  `datasetsWithHooks`
| *ndh* — normalises any declared dataset (`canmount=noauto`, snapshot props,
  post-mount hooks).

| The cluster dataset *layout* under `tank/rke2lab/*` (ephemeral `control-nodes/*`
  + `persist/*`)
| *rke2lab seed-outcluster* — published as `dataplan.json`, merged into
  `catalog.datasets`.

| The host datasets of ndh's own services, outside the catalog: `tank/nerd/attic` (the cache container's data, under

| *ndh* — the first made by `ndh-attic-dataset`, which applies its quota at every boot; the others by the container
  module's `create`, one per declared instance, renamed with it, removed only by the converge that made it.

== The contributor-merge

`catalog.datasets` uses the same merge law as
link:network-catalog-segments.adoc[network segments] — `catalog/merge.nix`'s `mergeByKey`, keyed by *dataset path*
instead of cidr:

* a contributor appends dataset records;
* records sharing a `path` are grouped;
* scalar fields (`type`, `mountpoint`, ZFS `options`) fold with `checkMerge` —
  a key defined by one contributor is unioned in, two contributors defining the
  *same* key with *different* values throws
  `dataset <path>: contributors disagree on <keys>`;
* first-seen path order is preserved.

The single current contributor is rke2lab's dataplan; the merge law is in
place so ndh (or another repo) can add host-side datasets under a shared tree
without silent clobber.

== The dataset entry shape

[source,nix]
----
{ path = "rke2lab/control-nodes/master/containerd";
  type = "zfs_fs";
  mountpoint = "legacy";
  options = { … }; }        # carried verbatim — extraction is behaviour-preserving
----

* `path` — relative to the pool root.
* `type` — `zfs_fs`.
* `mountpoint` — e.g. `legacy` for the containerd child.
* `options` — the ZFS property map, carried verbatim.

== Materialisation

`modules/nixos/zfs-disko-config.nix` folds the merged `catalog.datasets` into
`config.devices.zpool.tank.datasets` before the `datasetsWithHooks` pass, so every entry gets `canmount=noauto`,
snapshot props and post-mount hooks; `modules/nixos/disko.nix` passes it the catalog's `datasets`.

On a pool already provisioned, `modules/nixos/zfs.d/zpool-init.sh` creates a declared dataset that is missing, and
reconciles its mountpoint; it does not re-apply other properties of a dataset that exists.

== The root: `tank/rke2lab`

The layout root is `tank/rke2lab`: the datasets belong to the *rke2lab* project, not the `rke2` distro. `"rke2"` used
elsewhere as a node *kind* (`catalog.netplan … kind = "rke2"`, the tailnet host kind) is a different name.

== Persist and the recover pool

The cluster *persist* tier `tank/rke2lab/persist/*` (the Tailscale funnel Let's
Encrypt cert state, the render Maven cache) is retained across grows — a *sibling*
of `control-nodes/*` so the ephemeral wipe never reaches it. When ZFS replication
lands (link:zfs-snapshot-policy.adoc[the snapshot/replication policy] tentatively
plans *zrepl* into the `recover` pool), `tank/rke2lab/persist/*` is exactly the
replication set worth backing up — the ephemeral `control-nodes/*` is disposable.
The persist/ephemeral boundary the dataplan draws serves both semantics: *survives
a re-grow* and *worth replicating*.

== How to contribute a dataset

From rke2lab: add the entry to the `seed-outcluster` dataplan SSOT and publish the plan; ndh reads its
`dataplan.json` once its `fabric-plan` input is re-locked, and materialises it. From ndh (host-side datasets):
append to the `catalog.datasets` contributor list in `catalog/default.nix`.
