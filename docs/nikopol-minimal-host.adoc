= Corp Bare-Metal Minimal Host (vz.nikopol) Architecture
:toc:
:toclevels: 3

== Overview

`vz.nikopol` is the *corporate*, JAMF-managed macOS bare-metal (the MacBook Pro). The
design principle is to keep that host as *minimal* as possible — **it has no nix-darwin
configuration**; we only install packages into its nix store and run them, plus the
Tart/`vz` VM engine — while all personal development and the Incus workloads live *inside
Tart VMs* it hosts.

NOTE: naming. The corp bare-metal is addressed as `vz.nikopol` (`vz` = the VZ/Tart host
role). The *personal* environment is the Tart macOS VM `nikopol`. The Incus host is the
Tart NixOS VM `nikopol-nixos`. This document historically predates that split (it was
"alcide", and conflated host and VM); it now reflects the current three-part model. The
Incus stack is *Tart/`vz`-based — not Lima* (the earlier Lima/`incusbr0`/`192.168.106`
model is retired).

== Architecture

=== Three-tier design (Tart on corp bare-metal)

----

}

rectangle "nikopol\nTart macOS VM (personal)\ntailnet member" <<vm>> {

}

rectangle "nikopol-nixos — Tart NixOS VM\nIncus host · tailnet member" <<router>> {
    [Incus + lan-br]
    rectangle "lan-br .254/30 · ip_forward\nadvertises 172.16.6.0/24 (no NAT)" as LANBR
    rectangle "bare-br 172.16.6.0/25\ndnsmasq · dns.domain=nikopol\nhost-record vz.nikopol→.253" as ROAMBR
}

rectangle "Incus instances\n(collector.nikopol, apps · /25)" <<cluster>> as INCUS

EN0 <--> LANBR : static /30 · shared Wi-Fi L2 (bridged)
[Nix store + Tart/vz engine] --> nikopol : tart run --net-bridged=Wi-Fi
[Nix store + Tart/vz engine] --> LANBR : tart run --net-bridged=Wi-Fi
LANBR --> ROAMBR : routes /30 ↔ /25
ROAMBR --> INCUS : DHCP + .nikopol DNS
@enduml
----

Both Tart VMs bridge onto the *same Wi-Fi L2* as the corp Mac. `nikopol-nixos` runs the
baremetal instance segment `bare-br` (`172.16.6.0/25`, dnsmasq, `dns.domain=nikopol`),
forwards between the `/30` link and the `/25`, and *advertises* `172.16.6.0/24` into the
tailnet with a split-DNS `.nikopol` zone — so any tailnet peer resolves and reaches the
instances *and* `vz.nikopol` by name. No NAT. See
link:network-topology-c4.adoc[Baremetal Instance Segments & vz-host Access] for the full
transport (and the runtime-vs-declarative split on the Tailscale SaaS controller).

=== Layer responsibilities

==== Layer 1 — corp bare-metal (`vz.nikopol`, minimal, no darwin config)

*Purpose*: JAMF-managed, minimal interference with corporate policy. We do *not* own a
nix-darwin config for it; we install packages into its nix store and run them:

* the Tart/`vz` VM engine (VM lifecycle)
* the *baremetal-link package* (`pkgs/baremetal-link.d/`) — an idempotent script rendered
  from the catalog, delivered as text over `ssh` and run as root (deploy:
  `nix run .#nikopol-baremetal-link-deploy`; teardown: `-- --uninstall`).  It installs a
  WatchPaths LaunchDaemon that sets the `en0` alias `172.16.6.253/30` plus two routes via
  `.254`: `172.16.6.0/25` (reach the instances) and `100.64.0.0/10` (the no-NAT tailnet
  return path), re-applied on every Wi-Fi re-association

*NOT on the host*: heavy dev tools, container runtimes — and, by corp policy, *any VPN
binary* (no Tailscale/Headscale here; the Mac is reached via its Incus host's advertised
segment, never as a tailnet member).

==== Layer 2 — Tart VMs

* `nikopol` — personal macOS environment (the daily driver VM); a `mammoth-skate` member.
* `nikopol-nixos` — the NixOS Incus host: `lan-br` bridge, Incus, `ip_forward`; runs the
  `bare-br` segment and *advertises* `172.16.6.0/24` into the tailnet with the `.nikopol`
  split-DNS zone. A `mammoth-skate` member.

==== Layer 3 — Incus instances (on `nikopol-nixos`)

Workload containers/VMs on the managed `172.16.6.0/25` network (Incus dnsmasq, `.nikopol`
zone), including the netflow collector (`collector.nikopol` / `nnh`). The RKE2 cluster
stack proper is described by rke2lab (`vmnet-br`, `10.80.x`).

== Benefits

. *Compliance* — no darwin config + no VPN binary on the JAMF-managed Mac; only nix packages
  installed and run.
. *Isolation* — personal work and Incus workloads are inside VMs, off the corp host.
. *Named, tailnet-wide reach* — the advertised baremetal segment + split-DNS let peers
  resolve/reach `vz.nikopol` and the instances by name, on any network, without the Mac
  joining the tailnet; no NAT, so source IPs stay intact for flow attribution.

== Troubleshooting

=== Tart VM won't start

[source,bash]
----
tart list
tart run <vm> --net-bridged=Wi-Fi   # observe boot; see modules/darwin/tart-config.nix
----

=== Can't reach the corp Mac / instances by name

* Check split-DNS (`nikopol → 172.16.6.1`) + that `172.16.6.0/24` is approved in the tailnet.
* On the corp Mac: confirm the baremetal-link daemon ran — `ifconfig en0 | grep 172.16.6.253`
  and the two `.254` routes exist. See
  link:network-topology-c4.adoc#troubleshooting[the baremetal-link troubleshooting].
* Personal-env VMs: bridged on Wi-Fi; reach them on their LAN reservation (see
  link:network-setup.adoc[Network Setup] ranges).
