= Operator Commands (@codebase)
:toc: left
:icons: font

This document defines the canonical operator-facing command model.

== Principles

* Internal implementation scripts can remain colocated with modules.
* Operator entrypoints are exposed as short commands from Nix packages/apps.
* Host-bound operator app/package attributes are host-scoped with host-first naming (`<host>-nixos-*`).
* Avoid exposing internal `io-nxmatic-*` script names in `bin/`.

== Canonical Commands

* `<host>-nixos-bringup-install`
** Purpose: install/refresh the NDH bringup runtime profile.
** Flake app/package attribute example: `bioskop-nixos-bringup-install`.

* `<host>-nixos-lima-vm-materialize`
** Purpose: materialize Lima VM config and image links in the host profile.
** Flake app/package attribute example: `bioskop-nixos-lima-vm-materialize`.

* `<host>-nixos-tart-vm-materialize`
** Purpose: materialize Tart raw/ASIF image links in the host profile.
** Flake app/package attribute example: `bioskop-nixos-tart-vm-materialize`.

* `<host>-nixos-log-capture`
** Purpose: run a command, stream output to console, and save a timestamped log file (default under `/tmp`).
** Flake app/package attribute example: `bioskop-nixos-log-capture`.

* `<host>-nixos-tart-vm-bootstrap-installer`
** Purpose: launch Tart VM in installer bootstrap mode with recovery + installer ISO wiring.
** Flake app/package attribute example: `bioskop-nixos-tart-vm-bootstrap-installer`.

== Tart Disk Image Rematerialization (@codebase)

Use this procedure when you need to manually regenerate Tart VM disk images
outside of darwin activation.

* Standard rematerialization (rebuild root image, create missing data disks):
** `nix run .#bioskop-nixos-tart-vm-materialize`
** or `nix run /private/var/lib/git/nxmatic/nix-darwin-home#bioskop-nixos-tart-vm-materialize`

* Recommended pre-step before rematerialization:
** `tart stop nerd-nixos || true`

* Full reset rematerialization (recreate VM + all data disks):
** One-command factory reset mode:
*** `FACTORY_RESET=1 nix run .#bioskop-nixos-tart-vm-materialize`
** Equivalent manual sequence:
*** Stop VM: `tart stop nerd-nixos || true`
*** Remove VM and data disks:
**** `rm -rf ~/.tart/vms/nerd-nixos`
*** Re-run materializer:
**** `nix run .#bioskop-nixos-tart-vm-materialize`

* Notes:
** Root disk `disk.img` is created by `tart create` and kept in `~/.tart/vms/nerd-nixos/`.
** VM-local data disks `disk2` and `disk3` are created if missing in `~/.tart/vms/nerd-nixos/`.
** VM-local bootstrap image `nixos.img` is synced from configured Nix source into `~/.tart/vms/nerd-nixos/`.
** `FACTORY_RESET` accepts truthy values: `1`, `true`, `yes`, `on`.
When enabled, the materializer removes existing root/data images before rebuilding.
** To refresh only selected data disks, delete one or more of `~/.tart/vms/nerd-nixos/disk2`, `~/.tart/vms/nerd-nixos/disk3`, `~/.tart/vms/nerd-nixos/recover`, then run `nix run .#bioskop-nixos-tart-vm-materialize`.
** `run.sh` removes stale `~/.tart/vms/nerd-nixos/nixos.img` automatically once a ZFS partition is detected on `disk.img`.

== Command Output Capture Helper (@codebase)

Use this helper instead of manually appending `| tee /tmp/...` each time.

* Generic usage:
** `nix run .#bioskop-nixos-log-capture -- <command> [args...]`

* Example (capture a Nix build):
** `nix run .#bioskop-nixos-log-capture -- nix build .#darwinConfiguration.system -L -v -v`

* Optional naming/location:
** `nix run .#bioskop-nixos-log-capture -- --name darwin-rebuild --dir /tmp -- nix build .#darwinConfiguration.system -L -v -v`

* Environment defaults:
** `NDH_CAPTURE_DIR` (default `/tmp`)
** `NDH_CAPTURE_NAME` (default derived from command name)

The helper preserves the wrapped command's exit code and prints the created log path at the end.

=== Preferred Nix command workflow (@codebase)

When running Nix operations you may want to review with Copilot later, prefer wrapping
them with `<host>-nixos-log-capture` so logs are consistently archived in `/tmp`.

* Capture `nix build`:
** `nix run .#bioskop-nixos-log-capture -- --name nix-build-darwin -- nix build .#darwinConfiguration.system -L -v -v`

* Capture `nix run`:
** `nix run .#bioskop-nixos-log-capture -- --name tart-materialize -- env FACTORY_RESET=1 nix run .#bioskop-nixos-tart-vm-materialize`

* Capture `nixos-rebuild`:
** `nix run .#bioskop-nixos-log-capture -- --name nixos-rebuild-boot -- sudo nixos-rebuild boot --flake .#tart-bioskop-bringup-grub-zfs -L`

This replaces ad-hoc `2>&1 | tee /tmp/...` usage while keeping the same live terminal output behavior.

== Tart Serial Console Path Override (@codebase)

Generated Tart run wrapper now supports stable serial endpoint override.

* Default wrapper behavior:
** If no `SERIAL_PATH` is provided, wrapper uses Tart `--serial` default behavior.
** Auto PTY bridge is opt-in via `SERIAL_BRIDGE_ENABLE=1`.
** `--serial-path` (including auto bridge) is safety-gated and disabled by default due known Tart/VZ regressions.
** To force serial-path anyway, set `SERIAL_PATH_UNSAFE_ALLOW=1`.

* Optional auto bridge behavior (opt-in):
** Enable with: `SERIAL_PATH_UNSAFE_ALLOW=1 SERIAL_BRIDGE_ENABLE=1 ~/.tart/vms/nerd-nixos.sh`
** Wrapper creates PTY bridge with `socat` under `~/.tart/serial`.
** Tart endpoint: `~/.tart/serial/nerd-nixos.tart`
** Screen endpoint: `~/.tart/serial/nerd-nixos.screen`
** Wrapper prints exact `screen` attach command on startup.

* Runtime override:
** `SERIAL_PATH=/dev/ttys003 ~/.tart/vms/nerd-nixos.sh`

* Bridge tuning overrides:
** `SERIAL_ENABLE=0|1`
** `SERIAL_PATH_UNSAFE_ALLOW=0|1`
** `SERIAL_BRIDGE_ENABLE=0|1`
** `SERIAL_BRIDGE_DIR=~/.tart/serial`
** `SERIAL_BRIDGE_NAME=nerd-nixos`

* Behavior:
** If `SERIAL_PATH` points to an existing endpoint and `SERIAL_PATH_UNSAFE_ALLOW=1`, wrapper uses `--serial-path=<path>`.
** If path is missing, wrapper logs warning and falls back to `--serial`.
** If serial-path is not explicitly unsafe-allowed, wrapper logs warning and uses `--serial`.
** If `SERIAL_PATH` is unset and bridge is disabled or fails, wrapper uses `--serial`.

* Tip:
** Use a deterministic external endpoint path when possible, then attach `screen` to that same endpoint.

== Darwin Configuration Selectors (@codebase)

For each host, Darwin outputs expose one selected default plus explicit VM flavor variants:

* `{host}`
** Selected default Darwin configuration.
** Provider is controlled by `hosts/<host>/default.nix` via `hostProfile.vmProvider`.

* `{host}-lima`
** Explicit Darwin configuration aligned with Lima runtime (`<host>-nixos-lima`).

* `{host}-tart`
** Explicit Darwin configuration aligned with Tart runtime (`<host>-nixos-tart`).

Examples:

* `bioskop`
* `bioskop-lima`
* `bioskop-tart`

== Migration Rules

. Add/keep internal scripts under module-local `*.d/` folders.
. Expose only stable wrappers as operator commands.
. Name wrappers with short, task-oriented names (`nerd-nixos-<domain>-<action>`).
. Prefer one operator tool surface over per-script ad-hoc names.
