= Operator Commands (@codebase)
:toc: left
:icons: font

This document defines the canonical operator-facing command model.

== Principles

* Internal implementation scripts can remain colocated with modules.
* Operator entrypoints are exposed as short commands from Nix packages/apps.
* Host-bound operator app/package attributes are host-scoped with host-first naming (`<host>-*`, where `<host>` is the host alias/name — e.g. `bioskop-*`, `nikopol-*`, `nerd-nixos-*`).  The VM-materialisation app is the fixed `nerd-tart-vm-materialize` (keyed to the `nerd-nixos` VM, not per darwin host).
* Avoid exposing internal `io-nxmatic-*` script names in `bin/`.

== Canonical Commands

* `<host>-bringup-install`
** Purpose: install/refresh the NDH bringup runtime profile.
** Flake app/package attribute example: `bioskop-bringup-install`.

* `nerd-tart-vm-materialize`
** Purpose: materialize the Tart VM directory (`~/.tart/vms/nerd-nixos/`) — build the
   bringup image, `tart create` the root disk, create the ZFS data disks, write the
   run wrapper.  Fixed name (keyed to the `nerd-nixos` VM), not per darwin host.

* `nerd-tart-<host>-deploy`
** Purpose: copy the materialised bundle to a vz host and run the same activation there.
** Flake app/package attribute example: `nerd-tart-bioskop-deploy`.

* `<host>-log-capture`
** Purpose: run a command, stream output to console, and save a timestamped log file (default under `/tmp`).
** Flake app/package attribute example: `bioskop-log-capture`.

* `<host>-tart-vm-bootstrap-installer`
** Purpose: launch the Tart VM in installer bootstrap mode with recovery + installer ISO wiring.
** Flake app/package attribute example: `bioskop-tart-vm-bootstrap-installer` (fixed alias: `nerd-tart-vm-bootstrap-installer`).

== Tart Disk Image Rematerialization (@codebase)

Use this procedure when you need to manually regenerate Tart VM disk images
outside of darwin activation.

* Standard rematerialization (rebuild root image, create missing data disks):
** `nix run .#nerd-tart-vm-materialize`
** or `nix run /private/var/lib/git/nxmatic/nix-darwin-home#nerd-tart-vm-materialize`

* Recommended pre-step before rematerialization:
** `tart stop nerd-nixos || true`

* Full reset rematerialization (recreate VM + all data disks):
** One-command factory reset mode:
*** `VM_FACTORY_RESET=true nix run .#nerd-tart-vm-materialize`
** Equivalent manual sequence:
*** Stop VM: `tart stop nerd-nixos || true`
*** Remove VM and data disks:
**** `rm -rf ~/.tart/vms/nerd-nixos`
*** Re-run materializer:
**** `nix run .#nerd-tart-vm-materialize`

* Notes:
** Root disk `disk.img` is created by `tart create` and kept in `~/.tart/vms/nerd-nixos/`.
** VM-local ZFS data disks `tank1.img`, `tank2.img`, `tank3.img` and `recover.img` are created if missing in `~/.tart/vms/nerd-nixos/`.
** VM-local bootstrap image `nixos.img` is synced from configured Nix source into `~/.tart/vms/nerd-nixos/`.
** `VM_FACTORY_RESET` is executed directly as a shell command, so only the literal `true` enables it (not `1`/`yes`/`on`).  When enabled, the materializer stops+deletes the VM and wipes its directory before rebuilding.
** To refresh only selected data disks, delete one or more of `~/.tart/vms/nerd-nixos/tank1.img`, `tank2.img`, `tank3.img`, `recover.img`, then run `nix run .#nerd-tart-vm-materialize`.
** `run.sh` removes stale `~/.tart/vms/nerd-nixos/nixos.img` automatically once a ZFS partition is detected on `disk.img`.

== Command Output Capture Helper (@codebase)

Use this helper instead of manually appending `| tee /tmp/...` each time.

* Generic usage:
** `nix run .#bioskop-log-capture -- <command> [args...]`

* Example (capture a Nix build):
** `nix run .#bioskop-log-capture -- nix build .#darwinConfiguration.system -L -v -v`

* Optional naming/location:
** `nix run .#bioskop-log-capture -- --name darwin-rebuild --dir /tmp -- nix build .#darwinConfiguration.system -L -v -v`

* Environment defaults:
** `NDH_CAPTURE_DIR` (default `/tmp`)
** `NDH_CAPTURE_NAME` (default derived from command name)

The helper preserves the wrapped command's exit code and prints the created log path at the end.

=== Preferred Nix command workflow (@codebase)

When running Nix operations you may want to review with Copilot later, prefer wrapping
them with `<host>-log-capture` so logs are consistently archived in `/tmp`.

* Capture `nix build`:
** `nix run .#bioskop-log-capture -- --name nix-build-darwin -- nix build .#darwinConfiguration.system -L -v -v`

* Capture `nix run`:
** `nix run .#bioskop-log-capture -- --name tart-materialize -- env VM_FACTORY_RESET=true nix run .#nerd-tart-vm-materialize`

* Capture `nixos-rebuild`:
** `nix run .#bioskop-log-capture -- --name nixos-rebuild-boot -- sudo nixos-rebuild boot --flake .#tart-bioskop-bringup-grub-zfs -L`

This replaces ad-hoc `2>&1 | tee /tmp/...` usage while keeping the same live terminal output behavior.

== Tart Serial Console (@codebase)

The generated run wrapper (`~/.tart/vms/nerd-nixos.sh`) leaves the serial console
*off* by default.  Three mutually-exclusive modes are selected by environment
variables, in this precedence order (`modules/darwin/tart-config.d/run.sh`):

. `SERIAL_BRIDGE_ENABLE` — `socat` creates a PTY pair; tart opens one end
  (`--serial-path`) and you attach the other.  The pair lives under
  `~/.tart/vms/nerd-nixos/serial/`:
** tart endpoint: `~/.tart/vms/nerd-nixos/serial/nerd-nixos.tart`
** user endpoint: `~/.tart/vms/nerd-nixos/serial/nerd-nixos.screen`
** attach with: `screen ~/.tart/vms/nerd-nixos/serial/nerd-nixos.screen`
** with `SERIAL_BRIDGE_AUTO_SCREEN` also set, the wrapper starts a detached
   `screen` session named `nerd-nixos` (log at `~/.tart/vms/nerd-nixos/serial.log`);
   reattach with `screen -r nerd-nixos`.
. `SERIAL_PATH=<pty>` — you manage the PTY; the wrapper passes it through as
  `--serial-path=<pty>`.
. `SERIAL_ENABLE` — tart allocates its own PTY (`--serial`) and prints the path
  on startup.

* Truthy values for the enable flags are `1`, `true`, `yes`, `on`.
* `NO_GRAPHICS` runs the VM headless.

Examples:

[source,bash]
----
# Auto PTY bridge + auto screen session:
SERIAL_BRIDGE_ENABLE=1 SERIAL_BRIDGE_AUTO_SCREEN=1 ~/.tart/vms/nerd-nixos.sh
screen -r nerd-nixos

# Let tart allocate + print its own PTY:
SERIAL_ENABLE=1 ~/.tart/vms/nerd-nixos.sh

# Bring your own PTY:
SERIAL_PATH=/dev/ttys003 ~/.tart/vms/nerd-nixos.sh
----

== Darwin Configuration Selectors (@codebase)

For each host, Darwin outputs expose one selected default plus the explicit Tart variant:

* `{host}`
** Selected default Darwin configuration.
** Provider is controlled by `hosts/<host>/default.nix` via `hostProfile.vmProvider`.

* `{host}-tart`
** Explicit Darwin configuration aligned with Tart runtime (`<host>-nixos-tart`).

Examples:

* `bioskop`
* `bioskop-tart`

== Migration Rules

. Add/keep internal scripts under module-local `*.d/` folders.
. Expose only stable wrappers as operator commands.
. Name wrappers with short, task-oriented names (`nerd-nixos-<domain>-<action>`).
. Prefer one operator tool surface over per-script ad-hoc names.
