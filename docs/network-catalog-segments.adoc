:toc: macro

== Overview

*Network catalog segments* turn the catalog's per-baremetal entries into live
*Incus network segments advertised into the tailnet with split-DNS*, so any
tailnet peer can resolve and reach — *by name* — the workloads on a bare-metal
host and the host itself, including a *corporate Mac that cannot join the
tailnet*.

Each baremetal host (nikopol, bioskop) that runs Incus becomes the *subnet
router* for its own slice of `172.16.0.0/12`:

* a managed `bare-br` `/25` bridge (Incus dnsmasq, a `.<domain>` DNS zone) where
  netflow instances and the *nnh* collector attach and auto-register;
* the aggregate `/24` *advertised into the tailnet* + a *split-DNS* entry so peers
  resolve `<inst>.<domain>` and reach `172.16.6.x` directly;
* for a host whose vz-host is *off-tailnet* (nikopol's corporate Mac), a static
  `/30` link on `lan-br` and an IP-alias daemon on that Mac, so `vzhost.<domain>`
  answers at a `/30` address reached through the advertised segment;
* for a *LAN-fixed* host (bioskop, the always-on Mac Mini), the *whole home LAN*
  is advertised too, so roaming peers reach every LAN device.

Addresses are never hardcoded — they derive from
link:network-catalog.adoc[the network catalog] (`catalog.netplan.baremetal`).

== How to use it — attach a probe / service to a segment

This is how *nnh* (or any workload) plugs into a segment. From the Incus host:

[source,console]
----
# Launch on the segment bridge — DHCP gives it a 172.16.6.x lease and
# dnsmasq registers it as <name>.nikopol in the .nikopol zone.
$ incus launch images:debian/12 nnh --network bare-br
$ incus list nnh -c n4          # -> 172.16.6.x
----

From then on, from any *tag:console* tailnet peer:

[source,console]
----
$ ping nnh.nikopol              # split-DNS resolves .nikopol via the segment dnsmasq
$ curl http://nnh.nikopol:3000  # nnh's UI, reached over the advertised /24
----

| alias provider     | `baremetal-link` LaunchDaemon on the Mac (`nix run '.#nikopol-baremetal-link-deploy'`) | none — it is a real LAN host

|===

== Reachability model

Three independent gates must all pass — miss one and the name resolves but the
host is unreachable, or vice-versa:

. *Route advertised + approved* — the subnet router advertises `advertiseCidr`;
  `autoApprovers.routes` auto-approves it for `tag:nixos` (no console step).
. *ACL permits the CIDR* — a *tagged* peer's netmap only carries a subnet route
  its ACL allows. `tag:console` is granted the baremetal CIDRs *and* the fixed
  home LAN CIDR; without that a tagged Mac accepts the route but tailscaled
  filters it out. (An untagged member has `*:*` and never hits this.)
. *Name resolves* — a tailnet split-DNS entry `<domain> -> netGateway` serves
  Linux peers automatically; macOS additionally needs a *scoped*
  `/etc/resolver/<domain>` file (`modules/darwin/baremetal-resolvers.nix`) —
  the flat resolver list will not route a split-horizon domain.

== Operations

* *Tailnet auth + ACL* — `nix run '.#rotate-tailnet-secrets'` (dry-run by
  default): `--rotate-auth-key` mints the per-kind `tskey-auth-*` keys via the
  OAuth client; `--sync-acl` reconciles the SaaS ACL from the catalog;
  `--retag-devices` heals device tags. See
  `modules/.common.d/rotate-tailnet-secrets.d/`.
* *Deploy* — rebuild the Incus host on the branch (`nixos-rebuild-gh switch
  --refresh --flake …#<host>`). `advertise-routes` only re-applies on a fresh
  registration, so after a re-register run `tailscale set --advertise-routes=…`
  if the routes did not come back.
* *Corp-Mac alias* — `nix run '.#nikopol-baremetal-link-deploy'` installs/refreshes
  the IP-alias LaunchDaemon on `vzhost.nikopol` over ssh (no nix on the target).

== Troubleshooting

[cols="2,3"]
|===
| Symptom | Cause / fix

| Name resolves but host unreachable from a *tagged* Mac | ACL does not grant that
  tag the CIDR -> add it to the tag's `dst` (see reachability gate 2).
| `<name>.domain` won't resolve on macOS (`dig` "works", apps don't) | Missing
  `/etc/resolver/<domain>`. `dig` ignores scoped resolvers — test with
  `dscacheutil -q host -a name <name>`.
| Route shows advertised but not `enabled` | Auto-approvers evaluate at
  advertise-time only — re-advertise (`tailscale set --advertise-routes=…`) after
  a (re)tag.
| Advertised `192.168.1.x` route unused from a peer *on that LAN* | Correct: the
  peer's directly-connected LAN route shadows the tailnet route. The advertise is
  for *roaming/remote* peers.
| Incus instance can't reach a *LAN* service | `bare-br` has `ipv4.nat=false` and
  the LAN has no return route to `172.16.6.0/24`. *Known limitation* — needs
  selective masquerade on the subnet router or a LAN static route (planned).
| darwin activation hangs on `step crypto key format` | Unrelated to segments —
  see the ssh-keys pipeline; `step` opens `/dev/tty` (smallstep/cli#674); the
  conversion now uses `ssh-keygen -m PKCS8`.
|===

== Status & handoff to nnh

*From ndh's side this is ready.* The segment, its tailnet advertise, and the
catalog contribution path are implemented and verified end-to-end:

* ✅ `bare-br` segment provisioned on the Incus host (dnsmasq, `.<domain>` zone),
  reconciled idempotently (preseed + oneshot).
* ✅ `/24` advertised into the tailnet and *auto-approved* for `tag:nixos`;
  reached from `tag:console` peers (ACL grants the CIDR).
* ✅ Split-DNS live — Linux peers automatic, macOS via scoped
  `/etc/resolver/<domain>`; `vzhost.<domain>` resolves + is reachable (verified over
  SSH for nikopol's off-tailnet corp Mac).
* ✅ Catalog consumable as JSON (`nix eval --json '…#catalog.netplan.segments'`);
  contribution path defined (`lib.networkBlueprint` union — see
  link:network-catalog.adoc#contributing[Contributing]).
* ✅ Fleet on Tailscale SaaS; the headscale bootstrap daemon is retired (SaaS is
  the live control-plane).

*Known open item on the ndh side:* an Incus instance cannot yet reach *home-LAN*
services — `bare-br` runs `ipv4.nat=false` and the LAN has no return route to
`172.16.6.0/24`. Instance↔tailnet and instance↔instance work; instance→LAN needs
selective masquerade on the subnet router (or a LAN static route). Flag if nnh
needs LAN egress and we will land it.

*Over to nnh.* Please review whether this covers your needs:

* *Attach* — does launching the collector on `bare-br` (DHCP + `<name>.<domain>`,
  reachable over the advertised `/24`) match how you want the probe deployed?
* *Consume* — are `catalog.netplan.segments` (the `{cidr,name,asn}` triples) and
  `.asns` sufficient for your NetName/AS attribution, or do you need extra fields
  (e.g. per-segment metadata, IPv6 delegated prefixes)?
* *Contribute* — is `lib.networkBlueprint` the right shape for the spans you want
  to push back into the catalog, and do you want ndh to wire the `nnh` flake
  input now?

Tell us what is missing or wrong and we will provide/correct it.
