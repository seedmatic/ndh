== Technical Details

=== Deployment Approach

**rke2lab** (complex):
- Custom Debian images via distrobuilder
- Complex networking for Kubernetes
- ZFS, custom kernels, RKE2-specific packages
- Multi-file cloud-config merging

**incus-headscale** (simple):
- Standard Ubuntu 22.04 cloud images
- Simple cloud-init configuration
- No custom image building required
- Fast deployment via `incus launch`

=== Cloud-init Template Processing

**RKE2 (runtime):**
- Templates stay as `*.yaml.tmpl` in container
- Script `/usr/local/sbin/rke2-yaml-envsubst` runs at boot
- Uses `yq` + `envsubst` inside container

**Headscale (build-time):**
- Makefile processes templates during deployment
- `envsubst < template.yaml.tmpl > output.yaml`
- Variables substituted before cloud-init receives config

=== Makefile Comparison

**incus-headscale Makefile** (~100 lines):
```makefile
start: $(CLOUD_INIT_FILE)
	incus launch images:ubuntu/22.04/cloud $(NAME) \
		--config=cloud-init.user-data="$$(cat $(CLOUD_INIT_FILE))"
```

**rke2lab Makefile** (~700 lines):
- Image building with distrobuilder
- Complex network configuration
- Multiple cloud-config merging
- Extensive variable management

== Architecture Benefits

**✅ Clean Separation**
- RKE2 and Headscale are independent concerns
- Each project can evolve independently
- Clear boundaries and responsibilities

**✅ Shared Tools**
- No duplication of flox packages
- Consistent environment across projects
- Easy to add new tools (once in rke2, available everywhere)

**✅ Git Subtree**
- Work in standalone repos for focused development
- IDEA modules for cross-navigation
- Subtree for deployment integration
- Easy to version-lock or update independently

**✅ Simplified Deployment**
- Headscale: Simple, fast, standard images
- RKE2: Complex but isolated
- Each uses appropriate complexity level
