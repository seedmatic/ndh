This session built out the LAN-side declarative pipeline that the
upcoming nikopol enrollment depends on, and consolidated naming so
`mammoth-skate` is the one umbrella across the catalog, the SSH cert
authority, the TLS authority, the DDNS publication, and the LAN

  and queries the bbox JSON API at `/api/v1/dhcp/clients`, prints
  three buckets (missing, extra, drift) and exits 0 on a clean

  the catalog and the bbox state were already aligned.

. **Closed-world DNS zone `mammoth-skate.test`** — bioskop's dnsmasq

  follow the structured shape `<service>.<host>.<zone>` mirroring
  the SSH alias convention; queries for unmanaged names return
  NXDOMAIN.  `/etc/resolver/mammoth-skate.test` routes macOS

The session ended after `darwin-rebuild switch` on bioskop and

=== 5. `bbox-reconcile` (diff-only) ✅

`writeShellApplication` on every host's PATH where the catalog
declares a router.  Compares `catalog.netplan.lan.hosts` against
the bbox's `/api/v1/dhcp/clients`.  Three buckets:

* MISSING — declared in catalog, not on bbox (operator must add)
* EXTRA — on bbox, not in catalog (typically expected: TVs,
  speakers; suppressed via `lan-ignored-reservations.yaml`)
* DRIFT — same MAC on both sides, hostname or IP differs

Comparison key is MAC.  Implemented entirely in `yq-go` to avoid
pulling `jq` + `awk` into runtimeInputs.  Read-only by design;
write path is in `docs/bbox-api.adoc` but the body shape for
POST/PUT against `/dhcp/clients` hasn't been captured from the
bbox UI yet.

Closed-world: dnsmasq is told `local=/mammoth-skate.test/` so any
name in the zone NOT explicitly listed returns NXDOMAIN.  No
upstream forwarding — privacy-safe (no leak of private hostnames
to public resolvers) and fail-fast (typos surface immediately).

=== 7. dnsmasq auto-reload on config change ✅

Added `WatchPaths = [ "/etc/dnsmasq.conf" ]` to the dnsmasq launchd
daemon.  On every `darwin-rebuild switch` that produces a new
`dnsmasq.conf` (zone host added, IP changed, etc.), `nix-darwin`
atomically swaps `/etc/static`, the `/etc/dnsmasq.conf` symlink's
resolved inode changes, launchd's kqueue fires a vnode event and
bounces the daemon.  Operator no longer needs `launchctl
kickstart -k` after a switch.

== Technical Details

=== Why `.test` for the LAN zone

RFC 6761 §6.2 reserves `.test` permanently for "private testing
purposes; never publicly delegated".  Three properties matter:

* No registrar can sell it.  No future name collision.
* No public resolver caches answers under it.
* Historically established convention; some tooling has special
  cases for `.test` (no DNSSEC validation expected, etc.).

Alternative would have been `.lan` (already used by the bbox
auto-DNS), or a placeholder we plan to register later (e.g.
`.eu.org`).  `.test` was the safest choice for "permanently LAN-
internal" — the future public zone (whenever we register one)
gets a different name and the two coexist.

=== FQDN composition rule

Codified in `modules/.common.d/dns-zone-mammoth-skate.nix` via a
`kindShape` lookup:

[source,nix]
----
kindShape = {
  darwin-host = { emit = true;  service = _: "rdp-host"; };
  nixos       = { emit = true;  service = _: "nixos"; };
  vz-host     = { emit = true;  service = _: "vz-host"; };
  rke2        = { emit = true;  service = e: "${e.role}.rke2"; };
  wifi-iface  = { emit = false; };
};
----

Top-level hosts (no `parent`) emit at `<service>.<key>.<zone>`.
Nested hosts (parent set) emit at `<service>.<parent>.<zone>`.
RKE2 nodes have role mandatory — the renderer throws if a
`kind=rke2` entry lacks `role`, so a missing role doesn't silently
land an entry at `.rke2.<parent>.<zone>`.

=== Why CNAME aliases for top-level hosts only

Decision: structured-only naming except for muscle-memory aliases
on top-level hosts.  `bioskop.<zone>` and `nikopol.<zone>` get a
CNAME to the canonical `rdp-host.*` form.  Nested hosts
(`bioskop-nixos.<zone>`, etc.) do *not* get aliases — only the
structured form (`nixos.bioskop.<zone>`) resolves.

The reasoning: nested-host bbox-style aliases would leak the
"prefix conflation" the schema split was meant to fix.  Top-level
aliases are special because they're the operator's main entry
points; the muscle memory of typing `bioskop` is too valuable to
break.

=== `WatchPaths` semantics on Darwin

launchd uses `kqueue` with `EVFILT_VNODE`.  When a watched path
changes:

* Symlinks are followed; the watch is registered against the
  resolved inode.
* When `nix-darwin` atomically swaps `/etc/static` (during
  `darwin-rebuild switch`), the resolved inode behind
  `/etc/dnsmasq.conf` changes.
* kqueue fires `NOTE_LINK` (or rejects with ENOENT and re-arms);
  launchd interprets either as "config changed" and bounces the
  service.

Tested empirically: switch landed at 2026-05-16 14:59:30, dnsmasq
PID changed 68486 → 8934 within seconds without manual intervention.
