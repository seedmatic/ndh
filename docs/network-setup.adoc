== Overview

The fleet's cross-network reachability rests on a *Tailscale SaaS* tailnet,
`mammoth-skate` (`mammoth-skate.ts.net`), on which the always-on machines are members. The
home LAN is `192.168.1.0/24`, served by the Bouygues *Bbox* router (`192.168.1.254`, the
catalog router `mammoth-skate`). A *self-hosted Headscale* control plane is planned as a
*workload-cluster service* (hosted on the always-live bioskop workload) — it is **not
deployed today**; the mesh in use is the Tailscale SaaS tailnet.

[NOTE]
====
This document describes the *current* model — Tart VMs, `lan-br`, `mammoth-skate.ts.net`,
the personal/corporate ownership split, and the `172.16.6.0/24` baremetal segment. The earlier
*Lima* / `incusbr0` / `192.168.106` / `home.arpa` model is *retired*; if you find a
reference to it elsewhere, treat it as stale.
====

== Architecture

Two planes stack (full detail in the rke2lab mesh document):

* *Node plane — Tailscale, tailnet `mammoth-skate`.* Every always-on machine is a member:
  the NixOS Incus-host VMs (`bioskop-nixos`, `nikopol-nixos`) and the personal Macs/VMs.
  Always present — the bootstrap and external-access transport.
* *Workload plane — Headscale (future).* A distinct tailnet for workloads (pods/services),
  deployed as a service on the always-live bioskop workload cluster; absent until a
  workload runs.

[source]
----
┌───────────────────────────────────────────────────────────────┐
│  Node plane — Tailscale SaaS tailnet  mammoth-skate.ts.net      │
│  members: bioskop, nikopol (personal), bioskop-nixos,          │
│           nikopol-nixos  (+ cluster nodes)                     │
│  • identity-based SSH  • MagicDNS  • cross-network reachability │
└───────────────────────────────────────────────────────────────┘
        ▲                                          ▲
        │ (future) workload plane = Headscale       │  one exception: vz.nikopol (corp Mac)
        │  hosted on bioskop-wrkld                   │  cannot join → reached via nikopol-nixos's
        │                                            │  advertised baremetal segment +
        ▼                                            ▼  .nikopol split-DNS
   [ workloads / pods / services ]            [ see network-topology-c4.adoc ]
----

*One structural exception*: the *corporate bare-metal Mac* `vz.nikopol` (JAMF-managed)
cannot join the tailnet (no VPN binaries by policy). It is reached via its Incus host
`nikopol-nixos`'s *baremetal instance segment* (`172.16.6.0/24`), advertised into the
tailnet with a split-DNS `.nikopol` zone — resolved and reached by name, never as a tailnet
member. See link:network-topology-c4.adoc[Baremetal Instance Segments & vz-host Access].

== Network Topology

Two bare-metal hosts, each running a NixOS Tart VM that hosts Incus. The `-nixos` VM is the
Incus host and a tailnet member; the RKE2 workload cluster runs as Incus instances on it.

=== bioskop — Mac Mini · personal · always at home

[source]
----
bioskop (Darwin/macOS, .129)                     ← personal bare-metal, own hardware
├── Tailscale (mammoth-skate member)
└── nikopol-... Tart VMs
    └── bioskop-nixos (NixOS, .130)              ← Incus host · tailnet member
        ├── lan-br (bridged on the home LAN)
        ├── advertises 192.168.1.0/24 into the tailnet (LAN subnet router)
        └── Incus: bioskop-wrkld RKE2 cluster    ← 10.80.0.0/21 (vmnet-br)
----

=== vz.nikopol — corp MacBook · JAMF-managed · roaming

[source]
----
vz.nikopol (macOS, JAMF, .1)                     ← corporate bare-metal · NOT on tailnet
│                                                  (no darwin config; roaming pkg installed & run)
│   en0 (Wi-Fi) + alias 172.16.6.253/30 + routes /25 & 100.64/10 via .254
│
├── nikopol (Tart macOS VM, .33)                 ← personal env · tailnet member
└── nikopol-nixos (Tart NixOS VM, .34)           ← Incus host · tailnet member
    ├── lan-br (bridged on the LAN) + .254/30 · ip_forward
    ├── advertises 172.16.6.0/24 + .nikopol split-DNS into the tailnet
    ├── Incus: nikopol-wrkld RKE2 cluster        ← 10.80.8.0/21 (vmnet-br)
    └── Incus: roam-br 172.16.6.0/25 (dnsmasq, .nikopol) ← netflow (collector.nikopol)
----

The `172.16.6.0/24` baremetal segment is *advertised* into the tailnet with a `.nikopol`
split-DNS zone, so any peer resolves and reaches the instances and `vz.nikopol` by name (no
NAT). On the Tailscale SaaS controller today the advertise + split-DNS are console steps;
declarative under Headscale later. Full transport in
link:network-topology-c4.adoc[Baremetal Instance Segments & vz-host Access].

=== Home LAN reservations (from `catalog/default.nix`)

Static reservations live in `netplan.lan.hosts` (reconciled against the Bbox). `ownership`
labels each host `personal` or `corporate` (a flow-attribution label for `nnh`; ndh
reconciles both).

|===
| Host | IP | kind | ownership
| nikopol-vzhost (vz.nikopol) | 192.168.1.1 | vz-host | corporate
| zecoute / huematic / pop-screen / vertdegris / pop-cast | .5–.12 | media | personal
| nikopol | 192.168.1.33 | darwin-host | personal
| nikopol-nixos | 192.168.1.34 | nixos | personal
| nikopol-vz | 192.168.1.65 | vz-host | corporate
| bioskop | 192.168.1.129 | darwin-host | personal
| bioskop-nixos | 192.168.1.130 | nixos | personal

== SSH access (current model)

* *Across networks* — via the tailnet: `ssh <host>` (MagicDNS `mammoth-skate.ts.net`) or
  `tailscale ssh <host>`. Members: `bioskop`, `nikopol`, the `-nixos` hosts.
* *`vz.nikopol`* (off-tailnet corp Mac) — a real DNS name via the `.nikopol` split-DNS zone:
  `ssh vz.nikopol` resolves to `172.16.6.253` and reaches it over the advertised segment (no
  `HostName`/`ProxyJump`/resolver). See
  link:network-topology-c4.adoc#usage-patterns[the vz-host access usage patterns].
* SSH config is rendered per host by the ndh SSH modules; see
  link:modules-reference.adoc[Modules Reference] and the catalog `netplan.tailnet.hosts`.

== Security

* All tailnet traffic is WireGuard-encrypted; access is identity-based (no shared keys).
* The corp Mac runs *no VPN binary* (policy); it is reached via its Incus host's advertised
  baremetal segment + `.nikopol` split-DNS, never as a tailnet member. No NAT — source IPs
  preserved.
* Secrets (Bbox admin credential, tailnet auth) are sops-encrypted in `.secrets`; never
  commit plaintext.
