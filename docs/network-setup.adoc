== Overview

The fleet rests on **three tailnets** and one unmanaged LAN:

* **two self-managed tailnets, one per bare-metal** — each run by a headscale control plane in an
  Incus container on that bare-metal's NixOS guest, carrying the *infrastructure* nodes;
* **the Tailscale SaaS tailnet** `mammoth-skate` — carrying the *clusters* (their nodes and their
  tailscale-operator);
* **the home LAN** `192.168.1.0/24`, served by the Bouygues *Bbox* (`192.168.1.254`, the catalog
  router `mammoth-skate`) — deliberately **unmanaged**.

The design and its rationale are in link:fabric-control-plane-spec.adoc[Fabric Control Plane]; this
document is the operating map.

Authoritative sources (this doc is a map, not the source of truth):

== Architecture

[source]
----
┌──────────────────────────────┐      bridge       ┌──────────────────────────────┐
│ tailnet bioskop  (headscale) │ ◀═══════════════▶ │ tailnet nikopol  (headscale) │
│ bioskop, bioskop-nixos       │  gateway–gateway  │ nikopol, nikopol-nixos       │
│ control plane: container on  │                   │ control plane: container on  │
│ bioskop-nixos                │                   │ nikopol-nixos                │
└──────────────────────────────┘                   └──────────────────────────────┘
               ▲                                                  ▲
               │ segment routes                                   │ segment routes, and the
               │                                                  │ corporate bare-metal's /30
┌──────────────────────────────────────────────────────────────────────────────────┐
│ Tailscale SaaS tailnet  mammoth-skate — the clusters' nodes and their operator     │
└──────────────────────────────────────────────────────────────────────────────────┘
----

*One structural exception*: the corporate bare-metal `vzhost.nikopol` (JAMF-managed) can join no
tailnet — no VPN binaries by policy. It sits on `nikopol-nixos`'s `/30` link, inside the nikopol
segment's `/20`, and is reached by name through the `.nikopol` zone, never as a member.

== Network Topology

Two bare-metals, each running a NixOS Tart VM that is the Incus host, the segment gateway, and the
host of its segment's control plane.

=== bioskop — Mac Mini · personal · always at home

[source]
----
bioskop (Darwin/macOS, .129)                     ← personal bare-metal · roles: rdp-host, vz-host
├── member of the bioskop tailnet
└── Tart VM nerd-nixos — config bioskop-nixos (NixOS, .130)
    ├── member of the bioskop tailnet · gateway of the bioskop segment
    ├── lan-br (bridged on the home LAN)
    ├── advertises 172.16.0.0/20 (+ .bioskop split-DNS)
    ├── Incus container: headscale — control plane of the bioskop tailnet
    ├── Incus: bioskop-wrkld RKE2 cluster        ← 10.80.0.0/21 (vmnet-br) · SaaS tailnet
    └── fabric-br 172.16.0.0/21 (dnsmasq, .bioskop)
----

=== vzhost.nikopol — corporate bare-metal · JAMF-managed · roaming

[source]
----
vzhost.nikopol (macOS, JAMF)                     ← corporate bare-metal · member of NO tailnet
│   en0 (Wi-Fi) + alias 172.16.24.2/30 + routes via 172.16.24.1 (baremetal-link daemon)
│
├── nikopol (Tart macOS VM, .33)                 ← personal env · role: rdp-host · nikopol tailnet
└── nikopol-nixos (Tart NixOS VM, .34)           ← nikopol tailnet · gateway of the nikopol segment
    ├── lan-br (bridged on the LAN) + 172.16.24.1/30 · ip_forward
    ├── advertises 172.16.16.0/20 + .nikopol split-DNS
    ├── Incus container: headscale — control plane of the nikopol tailnet
    ├── Incus: nikopol-wrkld RKE2 cluster        ← 10.80.8.0/21 (vmnet-br) · SaaS tailnet
    └── fabric-br 172.16.16.0/21 (dnsmasq, .nikopol) ← netflow (collector.nikopol)
----

|===

Cluster CIDRs are derived from the `10.80.0.0/18` supernet (8 × /21, one per cluster; nodes as /23
within) by rke2lab's `ClusterNetworkBlueprint`, projected into this catalog via the `rke2lab` flake
input.

[NOTE]
====
The SaaS tailnet allocates from the whole `100.64.0.0/10`, so its addresses may coincide with a
headscale sub-prefix. No machine belongs to both, and traffic between tailnets targets segment
addresses, so the overlap is never seen.
====

== Names — private zones, one public name

We hold no authority over a public subdomain, so every zone is private. The single public name is
the Duck DNS host `mammoth-skate.duckdns.org` (`netplan.wan.ddnsHostname`), tracking the dynamic
public IPv4.

[options="header"]
|===
| Name | Zone | Serves
| `mammoth-skate.duckdns.org` | public | the emergency screen, the bridge endpoint
| `{instance}.bioskop`, `vzhost.bioskop`, `nixos.bioskop` | private, bioskop dnsmasq | the bioskop segment
| `{instance}.nikopol`, `vzhost.nikopol`, `nixos.nikopol` | private, nikopol dnsmasq | the nikopol segment, incl. its control plane's `server_url`
| `{instance}.bioskop` (the control plane) | private, bioskop dnsmasq | the bioskop control plane's `server_url`
|===

Each control URL is served over TLS with a leaf signed by the shared `mammoth-skate-tls` authority,
whose root every member already trusts — see
link:fabric-control-plane-spec.adoc#control-tls[Fabric Control Plane § TLS on the control URL].

== SSH access

[options="header"]
|===
| Situation | Path | Key
| managed, steady state | Tailscale SSH on port 2222, granted by the segment's policy | none
| a NixOS guest, any state | the serial console from its bare-metal (`screen -r {vm}-serial`) | none
| a cluster node | `incus exec` from its Incus host | none
| off-site and the segment down | the bbox VNC forward → bioskop's screen → `screen` on the serial console | none — the screen-sharing credential, from the password store
| `vzhost.nikopol` | from inside the nikopol segment, by its fabric name | per the segment's policy
|===

Cross-segment access targets the other segment's fabric names (`nixos.{host}`, `vzhost.{host}`),
never its MagicDNS names — see
link:fabric-control-plane-spec.adoc#_crossing_between_tailnets[Crossing between tailnets].

== Security

* All tailnet traffic is WireGuard-encrypted, and access is granted by policy.
* The corporate bare-metal runs *no VPN binary* and holds *no key*; it is reached over its
  segment, never as a tailnet member. No NAT — source IPs preserved.
* The home LAN is outside every policy; bioskop's screen there is guarded by the operator's macOS
  credentials, and is addressed by a name only the Bbox resolves.
* Secrets (Bbox admin credential, auth keys) are sops-encrypted in `.secrets`; never commit
  plaintext.
