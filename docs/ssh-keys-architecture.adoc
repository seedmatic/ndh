== Overview

The 2026-10-10 leak cost a full day, and a key that carries several roles turns one exposure into a
renewal of the fleet. This page fixes the model under which the next exposure renews one key.

Three ideas carry it:

. **One key, one role** — and the role decides who holds the private, who accepts the public, as which
  account (<<matrix>>).
. **One offline root, two delegations** (Figure 1, <<authorities>>).
. **Effort follows the lifecycle** (Figure 3, <<lifecycle>>): the full treatment goes to the keys
  everything stands on; the keys a control plane will replace get only the minimum safety.

[IMPORTANT]
.What changed on 2026-10-11
====
The previous revision of this page (decided 2026-10-06) said *"there is no SSH authority and no
certificate: a key is authorised where it is used, by a restricted `authorized_keys` line"*. The operator
reversed that on 2026-10-11: the fabric keeps SSH authorities — one for hosts, one for users — attested
by an offline root. What survives from 2026-10-06 unchanged: a key is generated by the machine that
uses it; a key is stable and renewed in two phases, never at activation; a key reaches only the role
that needs it; the emergency path is a screen.
====

[[authorities]]
== The authority model (Figure 1)

SSH (OpenSSH) and TLS (X.509) are unrelated formats, and OpenSSH has no chains — it trusts a flat
list of CA keys. A single root can still govern both, in two different ways:

* **TLS is a real chain.** `mammoth-skate tls` is an X.509 intermediate signed by the root and bounded
  by *name constraints*. The root is **ECDSA P-256** because Apple SecTrust validates the whole chain
  and refuses Ed25519 (the 2026-05-15 headscale failure). Every trust store anchors on the root alone.
* **SSH is attested.** The root signs one X.509 cross-certificate per SSH CA, carrying that CA's public
  key and naming its role (hosts or users). sshd never sees it. Our tooling does: the level-1
  projection check and activation assert that every CA key written to `TrustedUserCAKeys` and to
  `@cert-authority` lines is the one the root attests *for that role*, so the user CA can never pass
  as the host CA.
* **The root is offline**, in the password store, used only to sign or revoke a delegation. The
  delegated CAs sign on the **seat**, never on a runtime host: a host receives certificates, never an
  authority private.
* **One CA pair, no per-host authority.** The split is by role, not by host.

[WARNING]
.Name constraints are per name type
====
RFC 5280 applies `permittedSubtrees` separately to each name type. An intermediate constrained on DNS
names only can still sign any **IP** SAN, and the incus listeners present IP SANs. Constrain both: the
fabric DNS suffixes and the fabric and tailnet address ranges. Prove the chain on a throwaway against
Apple SecTrust before the renewal.

Constraints are inherited by everything below the intermediate. rke2lab's `ClusterSeal` roots every
cluster CA on this authority, so the constraints must also permit the cluster names
(`kubernetes.default.svc…`, the cluster's DNS names) and the service, pod and node ranges — or the
cluster PKI hangs off its own intermediate of the root. Decide which before the renewal.
====

[[lifecycle]]
== Lifecycle — the effort follows the column (Figure 3)

Everyday connections go through the control plane (Tailscale SSH, grants); the first emergency path is
a screen. So every key is classified, and the effort follows the class:

[cols="1,3,3",options="header"]
|===
| Lifecycle | What | Treatment

| **permanent**
| what everything stands on, even with control planes: the root, the delegated CAs, host keys, host age
identities, per-host nix signing keys, TLS leaves, the bridge keys, the control-plane credentials,
`cluster-age`, the GitHub keys
| the full plan: one role, a projection, a clean two-phase renewal, revocation

| **bootstrap**
| only until the tailnet exists: the bringup host key, tailnet pre-auth keys, and `nix-store` if Tailscale
SSH carries `nix-daemon --stdio`
| what it takes to start, then superseded

| **transitional**
| a batch role that a grant or another mechanism will replace: `sshfs` (→ virtiofs, to measure),
`baremetal-deploy`, `vz-nudge` (→ `tart exec`, to measure)
| the minimum: its own principal, its own account, a **recorded** slot (so it can be revoked), and the
name of what replaces it — nothing more

| **break-glass**
| the `operator` SSH key — the only one
| kept in the password store, loaded on demand with `ssh-add -t`, never at shell start, never forwarded
|===

The first emergency path is a screen, and its credential is known by heart and kept on paper, so
break-glass never depends on the seat that may be the thing that is broken.

The `operator` key has two states. Until fabric iteration 1 delivers Tailscale SSH, it is the everyday
access and sits in the seat's agent. Afterwards it moves to the password store. That demotion is tied
to the fabric milestone, not to the renewal.

== Principles

. **One key = one role.** No key is both a host identity and a human identity. A key that leaves its
  host is never also a decryption identity. A host key that never leaves its host may derive that host's
  age recipient (`ssh-to-age`), provided it is stable across image rebuilds.
. **A host key is generated on the host** and never comes from `keys.yaml`.
. **A principal names a role**, and only that role's key carries it.
. **Each account lists the principals it accepts**, never the union; root accepts none by default.
. **Privates are generated where they are used.** `keys.yaml` records publics and certificates; it
  holds a private only for material that must travel between seats.
. **The key that opens everything never travels** — the sops operator identity and the tailnet admin
  credential stay on the seats.
. **No authority private on a runtime host.** Certificates are signed on the seat from each consumer's
  public, and shipped as public certificates.
. **One signing rule: an authority signs with its OLDEST slot not marked `compromised`**, and presents
  that slot's root; the new generation signs only once phase 2 drops the old one, and a compromised
  slot never signs and leaves every trust store. Stated once in the schema, enforced by a check, in
  ndh and in rke2lab's keystore reader alike.
. **No key is generated at activation.** An unrecorded key cannot be revoked.
. **Each host receives a projection, computed, never placed by hand** (next section).
. **Effort follows the lifecycle** (<<lifecycle>>).

== Projections — how a key reaches a host

Every `keys.yaml` entry declares its **consumers** (who holds the private) and **acceptedBy** (which
account on which host accepts the public), resolved through the ndh inventory, and its **lifecycle**.
The host's configuration derives what it receives; a check refuses any drift.

* **Level 1** carries no secret: names, publics, certificates. Since host keys, guest identities, nix
  signing keys and TLS leaf keys are all generated on their hosts, and certificates are signed on the
  seat, the target is that **no runtime host decrypts `keys.yaml`**.
* **Level 2** therefore applies to ndh `.secrets`: each host gets a file encrypted for its own identity
  only.

The tasks that make level 1 the only channel for `keys.yaml` (<<to-target>>):

* `keys.yaml` is encrypted for the seats only;
* the runtime `ssh-keys.yaml` secret goes, once level 1 delivers the publics and certificates (6b);
* `ssh-add-keys` runs on the seat only;
* every host, guests included, presents its own host key, generated on that host (step 8).

== Usage patterns

=== ✅ Generate on the owner, sign on the seat

[source,bash]
----
ssh-keygen -t ed25519 -N "" -f /etc/ssh/ssh_host_ed25519_key     # on the host
# the seat records the public under keys.{key}.slots.{YY-MM-DD}.public,
# signs a host certificate with the ssh fabric HOSTS CA, and commits the certificate
----

The same shape holds for a TLS leaf: the key is generated on the server, the seat signs its CSR with
`mammoth-skate tls`.

=== ✅ One principal, one account

A batch key's certificate carries one principal, and only its account lists it:
`nix-store` → the `nix-store` account, `operator` → `nxmatic`, root → none.

=== ❌ One key for two roles

A key that is a host key, a login and a batch identity at once makes one exposure a renewal of
everything that accepts it.

=== ❌ A host key that comes from the seat

A host key copied from the seat is the seat's key, wherever it runs. A host key is generated on its
host.

=== ❌ An authority private on a runtime host

Signing at activation needs the authority private on every host that activates. Certificates are
signed on the seat.

=== ❌ An empty slot that "activation will fill"

A key generated at activation is never recorded, so it can be neither revoked nor evicted.

=== ❌ The principals union

A principals command that returns every principal for every account lets any certificate open any
account, root included. Each account lists its own.

=== ❌ Perfecting a key the control plane will replace

A transitional key gets its own principal, its own account and a recorded slot — and no more work.

== Troubleshooting

[cols="2,2,2",options="header"]
|===
| Symptom | Cause | Fix

| A client stops trusting a host after the switch to a seat-signed certificate
| the seat signed different principals from the ones activation used to sign (`hostname -f`, the
inventory names, `{host}-nixos`, `nixos.{host}`)
| reproduce exactly the runtime list from the inventory; compare before switching

| A TLS leaf fails under the new intermediate on macOS only
| the name constraints miss the leaf's IP SAN, or the root is not P-256
| constrain both DNS and IP; keep the root ECDSA P-256

| A retired generation still authenticates
| its slot was removed without a `revoked` entry
| phase 2 always writes both

| A guest cannot decrypt its secrets
| its own age identity is not a recipient yet
| re-encrypt its projection for the guest's public, from a seat

| After a two-slot renewal a TLS leaf does not chain
| the leaf was signed by one slot and chained to another slot's root
| one signing rule — signer and presented root are the same slot, the oldest not compromised
|===
