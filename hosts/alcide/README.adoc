= nikopol macOS VM (tart) bootstrap

nikopol now runs as a macOS VM via tart. Start it from the host with:
@codebase
[source,shell]
----
tart run nikopol --net-bridged="Wi-Fi" --vnc-experimental --root-disk-opts="sync=none,caching=cached" --dir="private:~/Private"
----
Inside the guest we still bootstrap Nix via flox. These steps keep SMB handled by ConnectMeNow, store git data on a dedicated APFS volume, and bring up the flox environment with GitHub auth.

NOTE: Nix no longer manages `/etc/nix/custom.conf`; if you create it manually, Nix will include it automatically.

== VM runtime (host)
- Install tart from the GitHub release and add it to your PATH (e.g., symlink the `macos` binary into `~/.local/bin`).
- If starting fresh, clone the base image once:
@codebase
[source,shell]
----
tart clone ghcr.io/cirruslabs/macos-tahoe-vanilla:latest nikopol
----
- Use the tart run command above to launch the VM with bridged Wi-Fi networking and the disk stored under `~/Private`.
- Keep the session VNC-enabled until SSH is set up if you need console access.

== First-boot account hygiene (guest)
- CRITICAL: do this before any Nix setup to avoid UID drift.
- The base image ships with an `admin` user; rename it to `nxmatic` so UID 501 stays aligned:
	- Create a temporary admin (e.g., `tempadmin`) and sign into it.
	- In Users & Groups → right-click `admin` → Advanced Options: set Account Name to `nxmatic`, Home directory to `/Users/nxmatic`, and keep UID at 501.
	- Rename the on-disk home to `/Users/nxmatic` if macOS didn’t; fix ownership from `tempadmin`:
@codebase
[source,shell]
----
sudo chown -R nxmatic:staff /Users/nxmatic
dscl . -read /Users/nxmatic UniqueID NFSHomeDirectory
----
	- Sign into `nxmatic`, verify `id -u` is 501 and sudo works. Remove `tempadmin` afterward.

== ConnectMeNow (SMB)
- Install ConnectMeNow and create a profile for the bioskop share (server, share name, username/password from macOS Keychain).
- Set it to auto-mount at login; this replaces the old autofs approach.
- Mount point can stay under `/Network/Servers/<host>/<share>`; leave the helper running so reconnections are automatic.

== APFS volume for git (guest)
@codebase
[source,shell]
----
# Find the APFS container (note its identifier like disk3s5)
diskutil list
# Add a case-sensitive APFS volume and mount it at /private/var/lib/git
sudo diskutil apfs addVolume <container> APFS GitStore -mountpoint /private/var/lib/git
sudo chown $USER:staff /private/var/lib/git
----
- `/var/lib` is the system symlink to `/private/var/lib`; mounting on the latter keeps the path stable.
- The APFS volume will auto-mount at boot; use `diskutil info /private/var/lib/git` to confirm.

== Flox + fleet env
@codebase
[source,shell]
----
# Install flox (official installer)
curl -S https://flox.dev/install.sh | bash
----
- Place the `nix-darwin-home` repo on the git volume (symlink an existing checkout from the bioskop disk, or clone if you prefer):
 - Use flox to avoid installing Xcode CLT just for git; flox provides git in its env.
 - Place the `nix-darwin-home` repo on the git volume (symlink an existing checkout from the bioskop disk, or clone if you prefer):
@codebase
[source,shell]
----
mkdir -p /private/var/lib/git/nxmatic
# Preferred: symlink from the bioskop-mounted checkout
ln -s /path/on/bioskop/disk/nix-darwin-home /private/var/lib/git/nxmatic/nix-darwin-home
# Optional: clone fresh instead
# GIT_SSH_COMMAND="ssh" git clone git@github.com:nxmatic/nix-darwin-home.git /private/var/lib/git/nxmatic/nix-darwin-home
----
- Activate the flox git environment from that checkout (persists XDG dirs under the project):
@codebase
[source,shell]
----
cd /private/var/lib/git/nxmatic/nix-darwin-home
flox activate git
----
- Build and activate the host configuration:
@codebase
[source,shell]
----
# In the flox environment
nix build .#darwinConfigurations.nikopol.system -o ./darwin
./darwin/sw/bin/darwin-rebuild switch --flake .#nikopol
# or, if activation script exists
sudo ./darwin/activate
----

== GitHub auth and token
- Inside the activated env, log in once so gh can use the token stored in Keychain:
@codebase
[source,shell]
----
gh auth login
----
- To use a custom token instead of browser auth:
@codebase
[source,shell]
----
# Export the token for this shell (or read from pass/Keychain) then feed it to gh
export GH_TOKEN="<personal-access-token>"
GH_TOKEN="$GH_TOKEN" gh auth login --with-token
----
- After auth, `gh auth status` should show the active user; flox env scripts will pick up `GH_TOKEN` if present.
